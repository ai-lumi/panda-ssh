## Context

已检查 `SftpSessionStore`：本地删除同步调用 FileManager；远端通过后台 FFI 调用标签会话。`sftp.rs` 递归删除无进度。`TransferStore` 的方向、字节进度与速度字段目前仅适用于传输。`SftpTabView` 的菜单操作才更新选区，而现有 workspace 规格要求展示菜单前完成。

2026-09-10 基线补充：

| 当前链路 | 已确认事实 | 本次处理 |
| --- | --- | --- |
| core `task_aggregation` → FFI `aggregate_task_groups_ffi` → `SftpSessionStore.aggregateItems` | 创建前分组已实际接入；目录上传转批量，下载按组建任务 | 复用，不回退到旧 `enqueueGroup` |
| `TransferStore.taskGroups` / `TransferGroup` | 仍按 groupID 组织视图并计算进度状态；core 有对应算法，旧 FFI `transfer_groups` 仍有独立实现 | 新增摘要复用 core 规则；逐步接入受影响汇总，不新增第三套规则 |
| `TransferStore.tick` → `transferChangeCounter` | 全局计数不变即跳过列表；单文件进度只改自身 version，批量模块未通知全局计数 | 先写失败测试确认，再修通完整通知链 |
| `SftpSessionStore.upload/download` | 扫描发生在正式任务入队之前 | 扫描前登记准备操作，交接时保证无漏计窗口 |
| FFI `group_to_record` | core 有 Delete，但 FFI 将其映射为 Upload | 新删除类型使用完整契约，禁止沿用此映射 |

既有分组核心 20 项及 FFI 4 项测试在上一轮检查通过；它们只验证分组，不证明实时刷新、前后台交互或双端构建通过。

## Goals / Non-Goals

目标是可响应、可放后台的删除与统一任务展示，保留既有传输状态机。仅新增删除专用执行器和类型化展示，不把所有业务改造成通用任务框架。

## Decisions

- Rust 核心承担本地和远程遍历/删除，抽象文件操作以便 fake 测试；使用显式栈进行后序遍历，不随目录深度增加调用栈。扫描不跟随符号链接；根目录、空目标和越界名称在启动前拒绝。
- 扫描与删除分阶段：扫描显示不定进度，完成扫描后按文件和目录项计数。每项处理后更新成功/失败计数；总项数不冒充字节数，失败不展示为成功。相比单阶段动态百分比，多一次扫描有成本，但分母稳定可核验。
- 新增删除任务记录/执行源，聚合到现有全局任务 Store 和页面。复用已有上传下载记录，避免把删除伪装成传输方向。仅在任务相关视图订阅进度，保留当前降低窗口重绘的改动。
- 同步 FFI 暴露启动、快照、取消与清理；异步复用全局 runtime。本地阻塞文件操作离开主线程。远程任务持有独立连接和运行所需凭据，不借用来源标签的连接生命周期；沿用主机密钥验证，不隐式信任。
- 删除确认时固定端点和完整目标路径。弹窗只控制展示，「放入后台」隐藏弹窗，不重启任务。后台指 App 运行期间，关闭来源标签/任务页不终止执行；不保证退出 App 或 iPadOS 系统挂起后继续。
- 删除支持协作式取消，当前文件操作结束后停止后续操作；不会恢复已删除内容。不提供暂停、自动重试或传输速度。失败项可查看，并在完成/失败/取消后刷新仍显示目标目录的文件栏。
- 菜单打开前同步更新选择：集合内保留，集合外替换为唯一目标并更新 anchor。菜单作用域由更新后的集合确定，不依赖陈旧的多选标记。macOS 原生菜单事件与 iPadOS 长按适配只负责界面事件，共用选择逻辑。

### 统一快照与变更通知

新增最小的类型化任务摘要：任务标识、操作标识、可选组标识、类型（上传/下载/本地删除/远端删除）、阶段、状态、端点、进度单位（字节/条目/未知）、已处理数、总数可选值、失败数和支持的操作。传输专有速度与目标路径按需附带；本地删除不要求 hostID，不能为满足旧模型填假值。

core 提供删除状态、汇总和未完成判定；FFI 将当前单文件、批量记录转换后交给 core 汇总，同时管理既有 runtime 适配。保持旧传输入口兼容，不要求先把历史执行器整体搬迁。Swift 的 TaskStore/任务源只做调用、映射和展示，保留原 TransferStore 的兼容层以缩小改动面。

所有会改变快照的事件都递增同一任务修订号，包括进度、错误、等待冲突、准备登记与交接、取消和清理。在源协议中暴露修订读取，测试源不依赖全局 FFI。读取时先记修订号，再读取列表；若读取期间有新事件，下一拍继续刷新，不在读取列表后记录一个未包含在快照内的新修订号。应用停机协调器直接通过后端任务登记与取消入口工作，不依赖 UI 缓存或定时器；通知可合并到现有刷新节奏，终态及时可见；无未完成任务时停止轮询。

准备阶段登记 operation ID，再执行扫描；失败/取消用统一清理路径收尾。转入正式任务时保留 operation ID，摘要按该 ID 去重，不能先删除准备记录再创建任务形成空档。既有目录批量任务只计一次，不再同时把它的展示组计入任务数。尚未实现的其他批量业务可后续接入此登记接口，本次不实现那些业务。

### 删除执行与退出细节

删除不复用过滤掉目录的传输分组计划：显式栈保留目录本身，符号链接按链接处理，扫描结束后按后序计划执行。可恢复的单项错误累计并继续无依赖兄弟项；扫描失败导致无法确定完整计划时终止该任务并报告错误，不显示虚假百分比。断连等不可继续错误终止任务，保留已处理计数。失败状态即使处理进度为 100% 也必须明确为失败。

默认弹窗只阻塞来源窗口交互。关闭任务页或来源标签不取消后台执行；取消按钮进入「正在取消」直到工作线程停止，避免过早宣称资源已释放。远程连接使用 Reject/显式信任流程，不复制现有传输中隐式 AcceptAndStore 的策略。

由 `add-tab-close-and-quit-shortcuts` 的第二次有效 CMD+Q 触发应用级停机时，本提案的任务登记先停止接受新工作，再对准备、扫描、排队、运行、暂停或等待决策中的任务发出协作取消。已有任务不要求正常完成；取消后的部分删除不视为回滚，远端执行状态不明时不重放。SFTP 任务完成本地清理和独立连接释放后向应用停机协调器报告，不显示任务审查或额外确认。

## Risks / Trade-offs

- 删除不可逆 → 保留原有确认，取消只停止后续操作；仅使用临时 fixture 和 fake 验证。
- 扫描增加网络往返及 O(条目数) 内存 → 扫描期间立即反馈；使用显式栈，避免调用栈溢出。暂不引入落盘队列。
- 扫描后目录发生变化 → 使用不跟随链接的操作并报告失败；不无界重扫、不扩展到新出现的目录树；通用 SFTP 无法保证其他进程并发替换路径时的原子隔离。
- 任务创建与凭据/标签生命周期交叉 → 创建时冻结必要上下文，任务资源在终态释放。
- 原生菜单事件时序 → 除 XCTest 外验证实际右键打开与取消菜单，不能只测点击菜单动作。

## Migration Plan

提案评审后，先验证并补齐刷新基础，再实现删除核心、类型化 FFI/摘要、UI 与退出保护；右键选择是独立的小批次。每批遵循测试→最小实现→重构。通过 Rust、Swift、覆盖率及双端构建后合并 delta 并归档。无持久化格式迁移，回退仅撤销本次增量，不重置已有用户改动。

## 统一停机参与补充

- `add-tab-close-and-quit-shortcuts` 拥有应用级退出入口与 2 秒二次 CMD+Q 交互；窗口关闭与退出应用分开处理，不擅自改变关闭窗口规则。本提案不新增菜单、Dock 或任务审查入口。
- SFTP 任务源在收到该协调器的停机请求时停止新登记、协作取消所有未完成任务，并在各自本地清理与独立连接释放后完成。协调器必须幂等，重复第二次按键不得重复取消或关闭。
- 统一任务源提供未完成工作摘要，覆盖准备、扫描、排队、运行、暂停、等待冲突决策及尚未生成子任务的批量操作。不能仅用当前 running/queued 轮询标记或角标判断。独立批量操作与子项明确所有权，避免重复计数和准备期漏计。
- AppKit 事件和浮层属于 macOS 平台服务/UI 适配，任务是否取消、连接是否关闭的业务事实来自统一核心状态。iPadOS 不增加程序化退出入口，也不承诺拦截系统终止。
- 影响映射追加：应用停机适配（验证 SFTP 任务取消与连接释放顺序）、任务登记门禁（验证停机后拒绝新任务）、任务未完成摘要（保留展示用途，不再驱动退出 UI）。保留任务进度局部订阅，避免 App 根视图高频更新。
