# 人工巡检闭环

> 状态：草案 | 创建日期：2026-09-09 | 关联路线图：brainstorming-ai-era-roadmap.md 5.5（首个纵向闭环）、8.4（场景地图）、8.7（决策 1/2/3）、13.1（主线 1 阶段 1.1–1.3）、14.8（测量契约优先）

## Why

首个纵向闭环（路线图 8.4 / 5.5）选择「人工触发的小规模主机巡检 + 一个故障初筛样例」，是批量执行、审计之外能独立验证价值的一环。当前 Panda SSH 只有连接监控（仅覆盖自身连接的传输状态），没有任何远程主机指标采集能力；更关键的是，没有测量契约的采集会把「缺失 / 过期 / 权限不足 / 解析失败」静默记为零或正常，制造主机全部正常的完整性假象。本提案以测量契约优先（14.8）的方式，先定义指标与失效边界，再定义采集、阈值与闭环流程。

## What Changes

- 新增巡检方案（InspectionProfile）实体：采集项、适用环境、解析规则、阈值、验证规则；可编辑、版本化。与执行计划、执行记录三分离（8.7 决策 1）：片段或方案更新不能使已审核的巡检自动改用新内容；执行记录不被方案更新改写。
- 新增测量契约：每项指标定义 key、单位、采样窗口、采集时间、适用系统与依赖、权限要求、解析规则版本、质量状态（至少：有效 / 不可用 / 不支持 / 采集失败 / 过期）与验证规则；缺失、过期、权限不足不得记为零或正常；部分失败不得把主机标为全部正常；跨主机分析保留时间偏差。并写清：连接监控≠远程主机指标采集，采集命令是真实 exec，不以「只读」免除授权。
- 首批指标从路线图 14.8 十个候选中选取首个闭环所需子集（初选：CPU 利用率、负载/核、内存使用率、文件系统容量、失败服务），逐指标写明测量与失效边界，不照搬未核验的通用阈值；最终取舍由 design 确认。
- 解析规则支持正则 / JSON 路径 / KV 三类；采集命令来源（CommandSource）支持内联命令或 SnippetRef；解析失败记为质量状态而非静默丢弃。
- 阈值检查按环境配置、使用可解释规则；触发结果展示给用户而非自动处置；「告警被忽略」不产生自动放宽。
- 人工闭环流程：目标选择 → 计划生成（共享契约：目标主机集合、凭据引用、跳板链、命令与展开后参数、引用内容版本标识、环境前提、验证步骤、资源预算、数据流向）→ 人工审核 → 有界采集执行（依赖批量执行契约）→ 应用内结果展示（有效指标 / 异常 / 缺失 / 过期分开展示）→ 人工验证复核与证据关联。
- 执行记录结构化持久化（SQLite 为选型方向，schema / 迁移 / 容量估算在 design 决策；与命令审计存储职责分开，不要求同库）。
- 应用内报告为首版必含；HTML 导出与报告模板作为提案内后续任务组（minijinja / uPlot 为候选，远端文本按不可信数据做上下文正确转义、不加载外部资源、展示采集失败 / 过期 / 审计缺段），不阻塞首版闭环。

## Capabilities

### New Capabilities

- `inspection-profiles`: 巡检方案的创建、编辑、版本化与适用环境规则；采集项与命令来源（内联 / SnippetRef）声明；方案更新与既有计划、执行记录的隔离边界。
- `inspection-measurements`: 测量契约——指标定义字段（key、单位、采样窗口、采集时间、适用系统与依赖、权限要求、解析规则版本、质量状态、验证规则）、三类解析规则、质量状态语义（缺失 / 过期 / 权限不足 / 解析失败的处理）、部分失败与跨主机时间偏差规则。
- `inspection-execution-loop`: 人工巡检闭环——目标选择与计划生成（绑定共享契约）、人工审核同一计划版本、有界采集执行、阈值评估与触发展示、结果展示分离、人工验证复核与证据关联、执行记录生命周期（尝试 / 状态 / 指标 / 验证 / 审计关联）。
- `inspection-reporting`: 应用内报告展示（首版必含）与离线 HTML 导出边界（远端文本按不可信数据转义、不加载外部资源、展示失败 / 过期 / 缺段、内置模板只读）。

### Modified Capabilities

（无）现有 `connection-monitoring`、`snippets`、`hosts` 等规格的需求不因本提案改变。连接监控与远程主机指标采集的边界澄清写入新规格 `inspection-measurements`；片段能力仅被 `CommandSource` 的 SnippetRef 方式引用，不改变片段规格自身需求。

## Impact

- **代码分层**：全部业务逻辑（方案模型与版本化、测量契约、解析器、阈值评估、闭环编排、执行记录存储）落 `crates/panda-core`，外部依赖用 trait 抽象隔离并 fake/mock 测试；`crates/panda-ffi` 保持同步导出（异步在既有全局 tokio runtime `block_on`），导出类型仅用简单值类型；Swift 侧仅 UI 与平台服务（钥匙串取凭据作参数传入），新增 `#if os()` 仅限 UI / 平台服务差异。
- **依赖提案（并行评审中，按共享契约对接）**：
  - `add-execution-plan-authorization`：执行计划模型、人工审核与授权生命周期；授权强制检查在 Rust 执行入口统一实施。
  - `add-batch-remote-execution`：CommandSource（内联 / SnippetRef）、有界采集执行、执行状态机九态、连接所有权（任务拥有自己的 Transport，不从终端标签隐式借用）。
  - `add-command-audit-trail`：审计关联（记录关联计划、批准、尝试与结果）、缺段可见；审计写入失败或完整性无法核验时阻断新的系统代发步骤。
  - `resolve-baseline-conflicts`：凭据基线表述消解；本提案不把「只存钥匙串」当作既定事实，涉及凭据时一律表述为「凭据引用（*_ref）+ 连接层按授权使用」，任务 / AI 无凭据读取能力。
- **新依赖（均须跨平台可编译、Apache-2.0 兼容）**：serde / toml（方案存储，已有）；SQLite 绑定 crate（选型与版本在 design 决策，需验证 Linux 可编译与 iOS 静态链接）；minijinja / uPlot 仅在 HTML 导出任务组经平台打包与资源占用验证后才引入，缺省不进依赖。
- **平台**：人工闭环与应用内报告 macOS / iPadOS 双端一致（业务逻辑全在 panda-core）；HTML 导出 macOS 直接落盘、iPadOS 经系统分享导出；定时巡检仅 macOS 且不在本批范围。

## Non-goals

- **macOS 定时巡检**（路线图 13.1 阶段 1.4–1.6）：Phase 2 单独提案。准入条件：计划经首次人工审核且人工执行验证无问题后，才可由用户启用定时；本提案不实现周期授权、调度与错失策略。
- **AI 摘要 / 解释 / 异常归因**（8.4「AI 实验」行）：不在此闭环引入模型调用。
- **重复任务**（8.4「重复任务」行）：不实现。
- **跨主机对比与历史趋势高级分析**：首版只保留逐主机结果与采集时间，不做跨主机聚合视图与长期趋势图表。
- **向量检索**（sqlite-vec）：保留为后续候选，未通过比较与平台验证前不引入。
- **拓扑发现**：不涉及。
- **PDF 导出**：不增加范围（8.7 决策 3 保留 HTML 方向）。
