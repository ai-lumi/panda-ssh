# add-manual-inspection-loop 任务清单

> 前置说明：第 8 组集成任务依赖三个并行提案（add-execution-plan-authorization、add-batch-remote-execution、add-command-audit-trail）的共享契约合并；合并前其余各组以 fake / trait 推进，不阻塞。所有实现任务前先列对应测试任务（红→绿→重构）；每个测试任务显式覆盖正常流程 / 意外操作 / 边界条件三类。Rust 全部落 `crates/panda-core`（新模块 `inspection`，结构见 design D7），FFI 保持同步导出，Swift 仅 UI / 平台服务。

## 1. 指标契约与注册表

- [ ] 1.1 测试：指标契约校验失败测试——正常（含单位、采样窗口、适用系统、权限要求、解析规则版本、质量状态判定、验证规则的完整定义注册成功）；意外（缺任一契约字段时注册被拒并指出缺失字段）；边界（重复 key 冲突、空 key 拒绝、无阈值无依赖的最小合法定义通过）。
- [ ] 1.2 实现：`metric` 子模块 MetricDefinition / MetricRegistry 与契约校验（未定义契约的指标不可被方案引用）。
- [ ] 1.3 测试：首批 5 指标定义失败测试——正常（5 指标按 design D2 完整注册、失效边界字段齐备）；意外（方案引用未注册指标报错）；边界（iowait 口径标注、计数器重置标记、窗口上下限 1–5 秒等标注字段齐全）。
- [ ] 1.4 实现：注册 `cpu.utilization`、`load.per.cpu`、`memory.usage`、`fs.capacity`、`systemd.failed_services` 及其测量与失效边界定义。

## 2. 解析器

- [ ] 2.1 测试：KV 解析器——正常（`key: value kB` 与 `key=value` 两式、单位后缀独立记录）；意外（非数值取值报解析错误）；边界（空输出、超长行、重复 key、注释与空行）。
- [ ] 2.2 实现：KV 解析器。
- [ ] 2.3 测试：正则解析器——正常（命名捕获组取值 + 指标声明单位）；意外（不匹配 → 解析错误状态而非丢弃）；边界（多行输出首个匹配、贪婪捕获、Unicode 与特殊字符）。
- [ ] 2.4 实现：正则解析器（regex crate）。
- [ ] 2.5 测试：JSON Pointer 解析器——正常（`/a/0/b` 取值成功）；意外（字段缺失、类型不符 → 解析错误）；边界（根指针、数组越界、null 值）。
- [ ] 2.6 实现：基于 serde_json pointer 的解析器，规则版本标注 `json-pointer@1`。
- [ ] 2.7 测试：解析通用行为——正常（成功结果含值 / 单位 / parser_version / 来源输出截断摘要）；意外（解析失败 → 「不可用」+ 错误信息 + 摘要保留）；边界（输出被截断时标记传递、exit≠0 与解析的优先级）。
- [ ] 2.8 实现：统一解析结果结构与摘要截断留存（默认每段 ≤2 KiB，可配）。

## 3. 阈值评估

- [ ] 3.1 测试：阈值评估器——正常（四种比较符的触发与不触发、环境默认 / 按主机 / 挂载点 scope 覆盖顺序）；意外（指标值缺失或非数值时不评估并记录原因、无匹配 scope 规则）；边界（等于阈值、计数+列表型指标 `systemd.failed_services` 的评估）。
- [ ] 3.2 实现：规则结构与评估器，产出可解释结果对象（指标、实际值、阈值、规则说明），无任何处置动作通道。

## 4. 巡检方案存储与版本化

- [ ] 4.1 测试：方案 CRUD——正常（创建 / 读取 / 更新 / 删除含三类解析规则与 SnippetRef 采集项的方案）；意外（引用未注册指标 key 拒保存、坏 TOML 拒载并报可区分错误）；边界（空采集项列表拒绝、删除方案后执行记录保留）。
- [ ] 4.2 测试：版本化——正常（每次保存修改产生新 SHA-256 版本、旧版本内容寻址副本可查且不变）；意外（不同内容产生不同版本、并发保存冲突检测）；边界（内容未变重复保存版本幂等）。
- [ ] 4.3 实现：TOML 存储 `inspection/profiles/` + `inspection/versions/<hash>` 内容寻址副本。

## 5. 执行记录存储（SQLite）

- [ ] 5.1 测试：库初始化与迁移——正常（v1 schema 建库、迁移版本表写入）；意外（库文件损坏报可区分错误、版本不识别拒绝打开）；边界（重复初始化幂等、store 根不存在时按 `init_store` 注入路径创建）。
- [ ] 5.2 实现：rusqlite（bundled）+ WAL，`inspection/inspection.db` 与 `schema_migrations`。
- [ ] 5.3 测试：运行 / 尝试 / 指标写入与查询——正常（一次完整运行落库并按 run / host / metric 查询，含采集时刻与窗口）；意外（quality 枚举外值拒绝写入、exit_code NULL 语义保留不映射成功）；边界（0 主机运行、单 run 大量指标批量事务写入）。
- [ ] 5.4 实现：runs / attempts / measurements / evidence / reviews 表与只写 + 查询接口。
- [ ] 5.5 测试：不可变性与清理——正常（按保留期清理保留 runs 头与「已清理」标记维持缺段可见）；意外（不存在任何更新历史记录的接口路径——以编译期与 API 面断言）；边界（删除方案后记录不变、应用重启后历史完整可查）。
- [ ] 5.6 实现：清理入口与手动清理命令。

## 6. 闭环 runner（fake 执行器先行）

- [ ] 6.1 测试：计划生成——正常（分组展开为具体主机 ID 集合、计划含命令与展开后参数 / 方案与片段版本标识 / 预算 / 数据流向）；意外（方案无采集项、目标集合为空时拒绝生成）；边界（生成后分组新增主机不进入计划——冻结目标集合断言）。
- [ ] 6.2 实现：计划组装（对接共享契约计划模型）与版本冻结。
- [ ] 6.3 测试：授权强制检查——正常（有效授权放行并记录授权引用）；意外（无授权 / 过期 / 计划版本不匹配 → 拒绝且 fake 执行器零调用）；边界（审计写入失败或完整性无法核验注入 → 阻断执行）。
- [ ] 6.4 实现：runner 执行前统一授权检查接入点（Rust 入口，UI 不替代）。
- [ ] 6.5 测试：有界执行——正常（并发 / 输出上限 / 总时长按预算执行、九态流转至成功并落库）；意外（单主机超时 → 「超时」且其余主机不受影响、exit_code None → 失败或结果未知绝不记成功）；边界（取消请求 → 停止等待 → 已确认停止 / 结果未知、全部主机失败、输出超上限截断标记）。
- [ ] 6.6 实现：runner 编排（`InspectionExecutor` trait + fake 实现完成全流程）。
- [ ] 6.7 测试：阈值评估与结果分类——正常（触发含原因展示、六类分栏结果模型）；意外（部分采集项失败的主机不标全部正常）；边界（全有效 / 全失败 / 全过期、用户忽略告警后方案阈值不变）。
- [ ] 6.8 实现：评估接入与分类结果模型。
- [ ] 6.9 测试：验证复核——正常（确认 / 有疑问 / 驳回落库含执行人与时间）；意外（对不存在运行或未完成运行复核被拒）；边界（复核不改写运行记录、重复复核为追加记录）。
- [ ] 6.10 实现：复核接口。

## 7. FFI 导出

- [ ] 7.1 测试：FFI 契约——正常（方案 CRUD、查询指标注册表、查询运行结果、写复核的往返序列化）；意外（无授权发起执行返回可区分错误码）；边界（导出全部为同步函数、类型仅 Record / Enum / Optional / String / 整数，无平台特有类型、无密钥材料字段）。
- [ ] 7.2 实现：`panda-ffi` 同步导出集（既有全局 tokio runtime `block_on`），凭据仅以 `*_ref` 出现。
