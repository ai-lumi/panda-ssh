# 提案：远程命令批量执行（add-batch-remote-execution）

> 关联路线图：`openspec/brainstorming-ai-era-roadmap.md` 5.3 提案 3、8.6（长任务）、13.1 主线 2；「首个纵向闭环」四提案之一。

## Why

现有 `SshSession::exec` / `exec_with_timeout` 只是单会话单命令原语（默认 60 秒超时）。运维者要在多台主机上执行同一命令时，只能逐个打开终端手工操作：无法受控并行、无法留痕审计、无法区分部分成功、崩溃后无从恢复，也不能在远端已执行但回包丢失时安全判断状态。本提案补齐「受控批量执行」契约，与授权（add-execution-plan-authorization）、审计（add-command-audit-trail）、人工巡检（add-manual-inspection-loop）共同构成首个纵向闭环。

## What Changes

- 新增批量远程执行能力：多选/分组解析为明确目标集合（展开为具体主机 ID），展开参数后生成执行计划送审，审批通过后有界并行执行。
- 引入执行任务九态状态机（排队、等待批准、运行、成功、失败、超时、取消请求、已确认停止、结果未知）并逐主机持久化状态与结果。
- 定义超时与取消语义：停止等待不等于远端已停止；结果未知保持可见；重连不自动重发；未收到退出码不得默认成功。
- 实施有界资源：主机并发、每主机步骤并发、输出大小上限、单步等待时间、任务总预算与背压策略。
- 提供崩溃恢复与重入核对：中断后先核对远端状态再决定恢复；部分成功不得汇总为全部成功。
- 提供业务验证步骤：执行成功与目标完成分别判断，验证步骤在计划中一并审核。
- 任务拥有自己的 Transport 与连接句柄，不从终端标签隐式借用。
- 计划、批准、尝试与结果关联审计，并消费审计阻断语义（审计不可用时阻断新的系统代发步骤）。
- UI 提供任务窗口查看逐主机结果（沿用传输任务窗口模式）；支持片段/历史入口与灰度批次、条件步骤（后续任务组）。

## Capabilities

### New Capabilities

- `batch-remote-execution`: 批量远程命令执行的完整契约——目标解析与计划送审、九态状态机与逐主机持久化、超时/取消/结果未知语义、有界资源与背压、崩溃恢复与重入核对、重试预算、业务验证、连接所有权、审计关联。

### Modified Capabilities

（无。连接所有权直接复用 `connection-pool` 既有「显式连接所有权」「按连接标识精确关闭」要求，批量任务作为一种新所有者类型接入，不改变其规格行为；授权与审计契约分别由 add-execution-plan-authorization、add-command-audit-trail 定义，本提案只消费。）

## Impact

- `crates/panda-core`：新增批量执行模块（计划展开、调度器、状态机、持久化、恢复核对），全部业务逻辑落在此层；外部依赖（SSH 连接、时钟、存储、审计）经 trait 抽象以便 fake 测试。
- `crates/panda-ffi`：新增同步导出函数——提交任务仅返回简单任务标识，状态/结果经轮询查询；异步执行留在既有全局 tokio runtime，不另起 runtime（路线图 8.6「长任务」约束）。
- `apple/PandaSSH`：任务窗口 UI（列表 + 逐主机详情 + 输出查看），参照 `Workspace/TransferPanelView.swift` / `TransferStore.swift` 模式；双端共享，无业务逻辑级 `#if os()`。
- 依赖提案：add-execution-plan-authorization（计划结构、审批状态、强制检查入口）、add-command-audit-trail（审计记录与阻断语义）、resolve-baseline-conflicts（connection-pool 残留复用条款清理）、improve-connection-reliability（重连语义边界：重连不自动重发）。

## Non-goals

- macOS 定时触发批量任务（定时仅 macOS，且不在本批范围；iPadOS 不支持定时执行）。
- 跨主机分布式同步或事务性编排。
- 滚动部署、批量补丁等高风险变更编排（单独提案）。
- MCP 调用入口（后续按扩展提案接入，遵循同一授权与审计契约）。
- 主机多维标签选择的数据模型（独立提案）；本提案仅用现有分组 + 多选。
- 通用回滚机制与恰好一次语义承诺（任意 shell 命令不可承诺）。

## 双端影响

- **macOS**：完整能力——手动发起批量执行、任务窗口查看、停止/恢复、片段与历史入口；定时触发不在本提案。
- **iPadOS**：同等支持手动发起与任务窗口；前台运行语义与 macOS 一致，App 切后台/被挂起时任务状态如实持久化，恢复前台后按「结果未知保持可见 + 重入核对」语义处理，不静默续跑也不误报成功；无定时执行、无服务器中转。
- 双端 UI 共享同一 Swift 源码，平台差异仅限窗口呈现与后台行为提示；授权校验、调度、状态机全部在 Rust 侧，双端行为一致。
