## Context

见 proposal.md。`WorkspaceStore` 已将单项与批量关闭的待确认状态分别建模为 `pendingCloseTabID` 与 `pendingBatchClose`；`WorkspaceView` 只负责将状态映射为系统控件并回调确认或取消。

## Goals / Non-Goals

**Goals:**

- 两个平台的关闭确认统一呈现为系统警告框。
- 保持状态机与连接释放时机不变。

**Non-Goals:**

- 不为纯 SwiftUI 呈现引入额外抽象或自定义对话框。
- 不修改 Rust、FFI、会话或传输逻辑。

## Decisions

### 1. 使用系统警告框而非确认菜单

关闭已连接终端会导致会话断开，是单一明确的破坏性确认；系统警告框能同时呈现后果、取消与破坏性动作，符合 macOS 与 iPadOS 的平台语义。确认菜单保留给多个同级动作的选择场景，因此不用于本变更。

### 2. 仅调整视图层

待确认状态、确认和取消回调已由 `WorkspaceStore` 覆盖测试；其语义不变。视图层只将四处确认菜单替换为警告框，并将确认按钮文案统一为「关闭并断开」。这避免重复业务规则，也不需要 FFI 改动。

### 3. 验证策略

现有 `WorkspaceStoreTests` 已覆盖单项与批量确认、取消、直接关闭和断开处理。系统控件类型是 SwiftUI 呈现细节，项目未配置 UI 测试 target；以 macOS 编译验证类型和平台可用性，并以手动双端检查验证实际呈现。

## Risks / Trade-offs

- [SwiftUI 系统呈现可能随系统版本有细微视觉差异] → 使用平台原生 `.alert`，并在 macOS 14+/iPadOS 17+ 目标上手动验证标题、正文、取消与破坏性按钮。
- [现有工作区文件有未提交改动] → 仅替换四个确认修饰符，保留其余差异。

## Migration Plan

1. 先运行既有关闭状态机测试，确认基线。
2. 替换呈现控件并重跑测试及 macOS 构建。
3. 在 macOS 与 iPadOS 手动确认单项和批量关闭；若出现平台回归，回退该视图层替换即可，状态机无需迁移。
