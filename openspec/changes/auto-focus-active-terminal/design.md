## Context

工作区为保活 SSH shell 会同时保留所有终端视图，只让活动终端可见且可交互。该架构避免了切换时断连，但系统不会因此自动更新原生第一响应者。

## Decision

终端包装器只在其对应标签页首次挂载为可见状态、或从隐藏切换为可见状态时请求焦点：macOS 在下一主线程循环调用窗口的 `makeFirstResponder`，保证视图已挂载；iPadOS 调用 `becomeFirstResponder()`。持续可见时不重复请求，避免无关界面更新抢占用户焦点；隐藏页签更新时不做任何焦点操作。

将“是否应请求焦点”的判断提取为纯值策略，以 XCTest 覆盖活动、非活动两类路径；平台调用仅保留在 UI 桥接层，符合平台条件编译约束。

## Risks

- 连接门控或失败页没有终端视图，因此不会提前抢占输入焦点；连接成功且终端挂载后才请求。
- 系统可能拒绝第一响应者请求（例如应用未激活）；这是平台行为，用户切回应用后仍可正常点击终端输入。
