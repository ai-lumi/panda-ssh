## Context

见 proposal.md。审计以当前仓库内的静态 Swift/Rust 名称引用为证据；SwiftUI、UIKit 与 SwiftTerm 的协议要求和应用入口不作为删除对象。

## Goals / Non-Goals

**Goals:**

- 仅移除在生产与测试源中均没有调用点的实现。
- 保持已有行为和公开 FFI 导出不变。
- 用编译和受影响测试确认删除没有留下引用错误。

**Non-Goals:**

- 不处理可能尚未接线、但仍被测试覆盖的产品能力。
- 不重组模块或修改任务、SFTP、连接状态的行为。

## Decisions

### 以静态引用为最小删除边界

删除对象必须同时满足“生产源仅有声明”和“测试源无引用”。这避免把测试作为唯一保留理由，也避免将 Swift 框架回调误判为死代码。

备选方案是清理所有仅测试引用代码；不采用，因为这些代码可能对应已规格化而尚未接入 UI 的能力。

### 保留 FFI 导出与框架入口

只删 Swift 对生成 FFI 的未调用包装，不删 UniFFI 导出函数、SwiftUI App 入口、UIKit/AppKit 构造或协议回调。

理由：这些入口的调用可能由运行时或生成绑定完成，静态检索不足以证明不可达。

## Risks / Trade-offs

- [静态检索漏掉反射或选择器调用] → 排除所有框架协议入口，并通过双端编译验证。
- [删除过时包装暴露外部调用] → 保持 FFI 生成接口不变；构建失败即恢复并重新评估。
- [删除后无行为测试覆盖] → 此变更不引入新行为，验收以引用清零、编译与既有测试通过为准。
