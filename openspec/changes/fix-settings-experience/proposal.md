## Why

设置页存在 iPadOS 无法明确关闭且暴露工作区页签、macOS 密文输入缺乏可发现性、保护操作状态与迁移失败可能不一致、多个分类只有占位内容的问题。终端回滚行数已有未实施提案，需要说明衔接关系，不能把规划中的能力当作可用设置。

## What Changes

- iPadOS 设置改为覆盖当前应用窗口的独立全屏页面，遮盖侧栏、工作区页签及内容，提供明确“关闭”按钮；关闭后回到原页面，保留会话、页签、历史与传输。
- macOS 保留系统 Settings Scene 和 `⌘,` 入口；使用清晰标签、提示文字及可辨识边界的密文输入框，保证受支持窗口尺寸内可访问；启用和换密钥增加再次输入确认。
- 密码保护明确区分未启用、已启用但锁定、已解锁及读取失败；拆分“解锁”“更换保护密码”“移除保护”，显示处理中/失败/成功反馈，避免成功后在输入框继续保留秘密。
- 按用户确认，加密范围仅为已保存的 SSH 密码和私钥口令。启用成功前自动迁移 `credentials.toml` 全部已有条目，不要求逐台主机重存；加强失败时磁盘、内存密钥与界面状态的一致性，保持现有凭据格式及算法。
- 移除”外观、连接、高级”等无实际功能的设置分类。仅”通用”可用时不绘制多余分类切换；终端缓冲区行数配置落地后顺序为”通用、终端”。
- 新增终端缓冲区行数配置：默认 10000 行，范围 1000–100000，仅新标签生效；配置校验由 Rust 提供，Swift 经 FFI 调用，不双份实现。终端表单使用原生整数输入控件，范围与生效范围合并为一条辅助说明，保存操作放在表单操作区末端。设置界面不显示内存估算。吸收原 `terminal-buffer-size` 提案的实施范围，旧稿保留但标记为已弃用。
- 设置页面中的显式提交、保存和危险操作按钮使用一致的末端对齐操作区；不改变由系统自动保存的选择控件的行为。

## Non-goals

- 不加密 `hosts.toml`、`groups.toml`、片段、`known_hosts`、日志、导出包或外部私钥文件；不改变导出归档排除凭据的规则，不引入系统钥匙串。
- 不实现运行时缩放缓冲区、页签内存指示器、设置界面内存估算或恢复失去的终端历史。
- 不改 macOS 工作区页签栏布局，不删除 SSH/SFTP 会话页签，不实现新的外观、连接或高级参数。
- 不新增第三方依赖、加密算法、全应用启动锁或跨进程凭据文件编辑支持；不承诺清除磁盘历史快照/备份中的旧明文，也不把原子替换等同于断电持久性保证。
- 本轮只交付分析与提案；不修改实现、测试、主规范或既有提案，不运行真实凭据迁移。

## Capabilities

### New Capabilities

- `settings-experience`: 两端设置导航与可用分类、可见可操作的保护密码表单、明确状态和异步操作反馈。
- `terminal-buffer-size`: 终端缓冲区行数配置、范围校验与终端初始化应用；配置校验由 Rust 提供，Swift 经 FFI 调用。

### Modified Capabilities

- `workspace`: 明确 iPad 设置全屏呈现时”导航与页签共用顶行”的可见性例外及关闭恢复行为。
- `credential-protection`: 补强自动迁移全部历史凭据、只解锁不改写、失败一致性、保护状态可查询与确认操作契约。
- `shell-terminal`: 补充缓冲区大小初始化要求；终端初始化时 MUST 读取用户配置并设置对应回滚行数。

## Impact

- SwiftUI：`SettingsView.swift`、`HostListView.swift`、`SidebarView.swift`、`PandaSSHApp.swift` 与 `WorkspaceView.swift`；设置呈现期间终端焦点资格及导入/导出模态宿主需回归。调整终端缓冲区数字表单与设置页显式操作按钮的对齐。
- Rust：`crates/panda-core/src/credentials.rs` 的保护状态、解锁与迁移事务；沿用现有凭据文件和受限权限原子写能力。`crates/panda-core/src/config.rs` 新增终端缓冲区行数默认值与原始文本校验。
- FFI：`crates/panda-ffi/src/ffi_store.rs`、`PandaCoreBridge.swift`；补充同步保护状态/只解锁接口，保持简单值类型，迁移工作不得阻塞 UI 主线程。新增缓冲区原始文本校验与默认值导出；Swift 仅负责 `UserDefaults` 读写，不在本地解析或校验业务规则。
- 测试：Swift 分类/表单/导航及双端界面验证，Rust 凭据故障注入与并发一致性、FFI 契约回归；按 Red → Green → Refactor 排序。新增缓冲区配置校验与终端初始化测试。
- 协同：保留工作区已有权限加固、导入安全、业务下沉和国际化改动；语言设置仍属”通用”，分类删除不由语言切换触发。`terminal-buffer-size` 旧稿标记为已弃用，本变更为唯一实施方。
- 本变更无磁盘格式破坏性变更；设置分类减少是有意的 UI 行为变化，需评审后实施。

## Migration Plan

1. 本轮只生成本目录规划文档，完成校验后等待用户批准。旧 `terminal-buffer-size` 提案在本变更归档时一并归档为已由本变更取代；本轮不修改旧稿。
2. 实施时先收集 macOS 复现证据，按 tasks 的失败测试顺序推进可信状态、事务、表单、iPad 容器与分类清理。
3. 文件格式不变，旧明文仍可读取；只有用户显式启用/更换/移除保护时才进行对应迁移。启用后文件受保护且本次进程已解锁，重启需重新输入保护密码。
4. 提交前失败保留原状态，可修复错误后重试；无需新文件格式回滚。版本回退不得自动移除加密或清空凭据，新版仍输出旧实现兼容的信封。
5. 终端缓冲区配置使用 `UserDefaults` 持久化，非敏感配置，无需钥匙串保护。配置变更后仅新标签生效，已打开终端不受影响。
6. 双端构建、Rust/Swift 测试及覆盖率验收完成后，再申请归档本变更；`terminal-buffer-size` 旧稿随本变更归档一并标记为已弃用。
