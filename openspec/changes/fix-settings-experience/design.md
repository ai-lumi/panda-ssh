## Goals / Non-Goals

**Goals:**
- 用原生呈现容器解决导航层级问题，工作区与终端对象不因打开设置被重建。
- 区分 UI 临时输入、Rust 可信保护状态与事务提交，避免设置页自己推断磁盘安全状态。
- 沿用既有加密信封和权限加固，用可注入 I/O 验证失败路径。
- 将”设置分类可用”与”未来计划”分开，本次直接交付终端缓冲区行数配置。
- 终端缓冲区配置校验由 Rust 提供，Swift 经 FFI 调用，遵循平台分层约束。

**Non-Goals:**
- 不重写工作区导航架构或建立通用插件/功能开关框架。
- 不设计全目录加密、不变更加密算法、不实现自动锁定计时器或跨进程文件锁。
- 不顺带重构整个导入导出或认证系统；只保证设置模态宿主及保护错误不被本次接线吞掉。
- 不承诺抵御进程内存读取、磁盘历史快照恢复或所有断电时序。

## Decisions

### 1. iPad 在根分栏之上呈现设置，而非替换工作区内容

在 `HostListView` 的 iPad `NavigationSplitView` 外挂原生 `fullScreenCover`，内部用独立 `NavigationStack` 承载设置与顶部“关闭”按钮。呈现状态独立于 `sidebarPage`，打开设置不覆盖原页面、主机选择和活动页签；在被呈现内容内获取 `dismiss`，不调用父窗口的 dismiss。这里“全屏”指当前应用 scene 的可用区域，不接管分屏中的其他应用。

工作区继续挂载，SSH 读取、终端历史和传输生命周期不变；单独将底层终端输入资格设为不可用，覆盖时不得请求 first responder、发送键盘输入或执行隐藏页签的切换/关闭快捷键。关闭时按当时仍有效的页面/活动页签恢复交互，不复活已经删除的主机或失效标签。

设置中的导入 sheet、iPad 分享界面和错误提示挂到当前设置宿主，不再从 `UIApplication.shared.connectedScenes.first` 猜测 root 并在已有全屏模态后方 present。子模态返回设置，不提前关闭设置或重置底层选择。设置更新过程中关闭按钮仍可见；事务提交期间禁用关闭和重复操作，显示进度，完成后恢复。尚未提交的秘密输入在关闭时清空。

替代方案：仅隐藏工作区 toolbar 不能同时解决侧栏、返回和焦点隔离；替换整个根视图容易销毁现有会话；普通 sheet 在 iPad 不保证遮盖工作区页签。故选用已有平台原生全屏呈现。

### 2. 保护表单采用明确动作和可见输入，不依赖占位字符串充当标签

macOS 继续走 Settings Scene；两端共用保护表单内容，平台分支只处理布局/键盘。采用稳定字段标签、独立 prompt、合适的输入宽度及 `.textFieldStyle(.roundedBorder)`；去掉强制固定高度裁切，保留合理最小尺寸与表单滚动。长标签、英文、深浅色、增大字号下字段仍能点击和键盘聚焦。

| 可信状态 | 可见内容与操作 |
|---|---|
| 未启用 | 明文风险与保护范围说明；新保护密码、确认保护密码；“启用密码保护” |
| 已启用、锁定 | 当前保护密码；“解锁”；不把空新密码解释成另一种动作 |
| 已启用、已解锁 | 明确已解锁；可进入“更换保护密码”（当前、新、确认）或“移除保护”（当前密码与明文风险确认） |
| 读取失败 | 明确错误与重试；禁用可能覆盖凭据的操作，不降级成未启用 |
| 操作中 | 进度及不可重复提交状态；不提前显示已保护或关闭页面 |

启用/变更新密码必须非空且两次一致；不新增未经评审的长度/复杂度策略，不 trim 或规范化秘密字符，空白和 Unicode 按原值验证。新旧密码完全相同时，在验证当前密码后仍重新加密文件并更新盐/nonce，确保每次变更都产生新的加密材料。展示层负责交互，最终验证与保护状态由 Rust 提供。移除保护必须重新输入当前密码并确认，不能仅利用隐藏缓存执行降级。macOS 按活动窗口隔离输入，设置窗口保持打开但用户切回主窗口时终端仍正常接收输入，不复用 iPad 全屏覆盖期间的全局禁用条件。

Swift 通过可注入的轻量操作适配器调用 Bridge，在后台调用现有同步 FFI，不在 UI 主线程执行 Argon2、磁盘 I/O、状态查询或等待凭据事务锁；不另起 Rust runtime。操作完成后仍在后台重新读取可信状态，仅将结果发布、密码字段清空和界面更新切回主线程，成功提示指出“已保护所有已保存的密码与私钥口令”，不声称所有配置均已加密。进入页面、应用重新激活及保护动作完成后均以同一后台路径刷新状态，过期查询结果不得覆盖更新操作之后的新状态。

替代方案：保留“解锁或更新”单按钮虽然代码少，但空输入决定操作语义且解锁也写盘，难以清晰验证；只加边框而不修可信状态无法解决迁移失败后误报。

### 3. 可信状态与只解锁入口由 Rust 提供

保留既有同步保护更新导出以避免破坏调用方，新增简单枚举状态（未保护/受保护锁定/受保护已解锁）和独立只解锁操作；读取/格式/认证失败继续走 Result，不混入“未保护”。FFI 不返回密钥、密文或凭据明文作为状态。既有更新入口的兼容参数契约不变；设置表单明确动作后只传动作对应的字段。

状态查询验证文件格式；内存密钥只有通过认证后才使状态成为已解锁。只解锁在临时变量中验证现有文件，成功后发布内存密钥，不重写文件或刷新盐/nonce。错误候选密钥不得清空先前仍有效的已解锁状态。启动不持久化保护密钥，因此重新启动后的加密凭据处于锁定态；主机列表仍可访问，不引入全应用启动锁。

既有凭据读取中的保护错误应保持可区分，不得由新适配器吞为 false/空密码；密码与私钥口令两条调用链均列入回归。该要求已属于正式规范，若现有吞错点阻止验收，只修改该点的错误传递而不重做认证流程。

### 4. 凭据迁移采用先准备、后提交、再发布内存状态

在现有 `CredentialStore` 内使用同一事务边界串行化读取、保存、删除、只解锁和保护变更。加锁后读取现有条目，以传入候选旧密钥在局部验证；新密钥与新信封也在局部准备。锁持有期间不回调外部观察者，使用接收显式 key 的内部方法，避免当前 read/write 再次取得同一锁而死锁。

- 读取/认证/序列化/加密失败：没有可见变更，保留原文件，丢弃本次候选密钥并尽力清理本次创建的临时文件；若调用前已有与原文件匹配的已解锁密钥，必须保留它，若没有则保持锁定或未保护状态。
- 准备写入：复用同目录随机、独占创建的临时文件；秘密写入前即限制权限。必要权限检查和写入检查放在提交前。
- 提交点：同目录原子 rename 成功。调用中唯一从旧状态切换到新状态的时刻是此提交点；随后发布对应内存密钥与保护状态。
- 现有 rename 后可失败的重复 chmod 不得再导致”磁盘已经换密钥，内存却回到旧密钥”。优先把所有必要权限设置/验证移至临时文件提交前，利用替换后的同一文件权限；若保留提交后检查，结果必须能区分”未提交失败”和”已提交但后置检查异常”，保留与已提交文件匹配的内存密钥，界面不得谎报回滚成功。
- 任一提交前失败尽力清理本次临时文件并丢弃本次候选密钥；不得清除调用前已验证且仍与原文件匹配的内存密钥。不创建长期明文备份，不触及不相关文件。即使清理失败，残留临时文件也必须受限权限并报告可恢复错误。

迁移覆盖全部凭据引用和值，原先没有文件/没有条目时也允许建立受保护的空存储。更换/移除保护遵守同一提交语义。并发保存、删除必须在线性化顺序中保留结果，不得用迁移前的旧快照覆盖其后已成功保存的条目。

测试注入点是凭据 I/O 层的创建、写入、权限检查、提交，不改变生产文件路径，也不以修改真实配置目录权限来制造故障。加固提案要求的 0600、独占临时文件、防临时符号链接复用、专属目录 0700 与 iPad App Group 例外全部保留。

替代方案：只在错误分支恢复一个内存变量无法解决先发布状态、并发读改写丢条目和提交后误报；全目录事务系统、另换加密容器属于不必要扩张。本设计限定单一凭据文件与当前进程。

### 5. 设置只展示已实现的分类

本变更移除外观、连接、高级的”即将上线”视图。终端分类在本次交付缓冲区行数配置后恢复展示，顺序固定为通用、终端。导入导出、密码保护、关于保留在通用，国际化提案的语言项继续放通用。

仅通用可用时直接展示通用表单，不保留空 TabView 导航。本次不创建空终端页、不用运行时猜测后端符号或新增功能开关系统。测试以”每个展示分类有实际内容”和相应版本的明确分类清单断言，不继续锁死五个占位枚举。旧分类选择若不再存在，回到通用，绝不删除会话标签或配置数据。

### 6. 终端缓冲区行数配置

**用户决定：将原 `terminal-buffer-size` 提案合并到本变更实施，旧稿保留但标记为已弃用。**

缓冲区”高度”指 scrollback 历史行数，不是视口像素高度、PTY rows 或 Rust 接收字节队列容量。默认 10000 行，范围 1000–100000，仅新标签生效。设置界面不显示内存估算，避免旧稿中 `Cell`/`CharData` 大小不准确导致的误导。

配置校验由 Rust 在 `crates/panda-core/src/config.rs` 提供，包括默认值、原始文本解析和范围检查；FFI 导出 `default_terminal_buffer_lines() -> u32` 与 `validate_terminal_buffer_lines(raw: String) -> Result<u32>` 等效契约。Swift 将设置表单的未解析文本和从 `UserDefaults` 读取的原始值交给该 FFI，并只持久化 Rust 返回的规范化整数；Swift 不自行解析、夹限或决定默认值。持久化使用 `UserDefaults`，非敏感配置无需钥匙串保护。

终端初始化时读取当前配置快照，在首批输出前应用。已打开的终端保持其创建时的缓冲区大小，配置变更不追溯。重连同一标签、切换页面和 SwiftUI 重建不得偷偷读新配置覆盖旧快照。SwiftTerm `AppleTerminalView.swift:2229` 已有公开 `changeScrollback`，但本次仅在初始化时使用，不实现运行时动态调整。

旧稿矛盾之处（tasks 1.2 固定 160 列 vs design 使用平均列数/80 列）不再适用，因本次不显示内存估算。旧 `shell-terminal` delta 修改整个”终端数据流”的问题改为独立回滚初始化 requirement，避免与 `fix-ssh-session-failure-diagnostics` 重叠。

### 6.1 终端缓冲区表单与设置操作区

回滚行数是整数配置，而非自由文本；表单使用平台原生数字输入方式。macOS 使用可直接编辑的整数输入并提供步进操作，iPadOS 调用数字键盘；键盘输入、粘贴和辅助技术仍可能带来非法原始值，因此最终默认值、解析和范围判断继续只由 Rust FFI 执行。输入控件本身不重复定义业务范围规则。

范围和生效范围合并成输入框下的一条辅助说明：`范围 1000–100000；仅对新打开的终端标签生效。` 输入框内不再重复范围占位文本，避免在窄宽度、动态字号或本地化时出现第二处提示折行。

设置中的显式提交、保存和危险操作统一置于各自表单分区的末端操作区，并在左至右阅读方向上视觉右对齐；不把复选框、选择器等即时保存控件伪装成提交操作。该约定让用户在不同设置分区中以一致位置找到会产生提交效果的按钮，同时不改变既有保存语义或保护操作的确认要求。

替代方案：显示内存估算需要准确知道 `CharData` 大小和终端列数，增加复杂度且估算值可能误导用户；按主机单独设置增加配置复杂度，本期不实现。

### 7. 相关提案协调

- `harden-credential-file-permissions`：保留受限权限与临时文件安全，不以恢复明文/放宽权限绕过故障；提交后检查时序须共同回归。
- `fix-config-import-zip-slip`：不触及导入白名单、预检和路径防护；仅调整 iPad 呈现宿主。
- `add-app-internationalization`：新增标签/prompt/状态/错误沿用已有资源机制。其“不改变标签顺序”约束的是语言切换，本次有意删除无用分类但保留可用分类相对顺序，不让两者互相恢复旧占位页；归档前审查实际合并结果。
- `migrate-business-logic-to-rust`：保护状态、凭据变更及缓冲区配置规则仍属于 Rust；`UserDefaults` 仅为 Swift 平台持久化适配层。已有公钥路径吞保护错误不能借业务下沉继续保留。
- macOS 页签拖动/标题栏修复：本次不改其 chrome，只回归设置打开不影响窗口页签或缩放。

### 8. 技术可行性依据与验证边界

已读取 Apple 官方正文（2026-09-17），现有最低平台版本均覆盖这些 API：

1. [fullScreenCover](https://developer.apple.com/documentation/swiftui/view/fullScreenCover(isPresented:onDismiss:content:).md)：iPadOS 14 起提供原生覆盖呈现；本项目 iPadOS 17+ 可用。
2. [DismissAction](https://developer.apple.com/documentation/swiftui/dismissaction.md)：必须在被呈现视图的环境内获取，父视图环境的 dismiss 可能无效甚至关闭窗口。
3. [SecureField](https://developer.apple.com/documentation/swiftui/securefield.md)：macOS 10.15 起支持；官方明确 macOS Form 将 label 放在输入框前、prompt 放框内，并示例 roundedBorder。支持“明确标签＋提示＋可见边界”方案，但不证明当前实际不可见的唯一根因。
4. SwiftTerm 当前本地官方依赖源码：`apple/DerivedData/SourcePackages/checkouts/SwiftTerm/Sources/SwiftTerm/TerminalOptions.swift:67–88`（默认 500）；`Apple/AppleTerminalView.swift:2224–2234`（公开更改回滚行数）。本次实现将在终端初始化时应用用户配置的 scrollback 值。
5. [Rust rename 官方文档](https://doc.rust-lang.org/std/fs/fn.rename.html) 本轮抓取遇 DNS 失败，当前 shell 也未提供 `rustc`；不把未读取页面当作已验证证据。凭据事务结论来自现有源码和规范，实施前应在项目 Rust 构建环境核对文件替换语义并做故障注入验证。

官方 Apple 文档已覆盖所选 UI API，无需先引入社区 workaround 或自制呈现框架；当前并未进行运行验证或性能测量。正式实现前需评审本方案，出现与官方描述不同的实测结果时再查相应官方论坛/社区证据，不用猜测反复改布局。

## Risks / Trade-offs

- [输入框问题尚未实机复现] → 第一项实现准备任务保留截图/尺寸/焦点证据，再写回归测试，不宣称单改样式必然解决。
- [遮盖设置导致终端抢焦点或重连] → 分离呈现与会话生命周期，验证会话 ID、历史和输入记录，覆盖旋转及窄分屏。
- [增加确认字段使表单更高] → 可滚动、自适应布局，确保按钮始终可达，不扩大为新窗口管理方案。
- [同步 KDF 与事务锁延迟其他凭据操作] → 后台调用、有限单次提交与明确进度；不持 UI 主线程，不在锁内回调。
- [提交后失败被误当成已回滚] → 明确提交点，测试磁盘与内存状态相符，不在任意 catch 中复位旧密钥。
- [旧明文存在外部备份或系统快照] → 保护范围限定当前凭据文件，不承诺安全擦除历史副本。
- [缓冲区设置过大导致内存压力] → 最大限制 100000 行，不显示内存估算但范围已约束；用户可根据实际使用调整。
- [配置变更后旧终端不一致] → 明确仅新标签生效是产品取舍，避免运行时截断历史内容；用户可关闭旧标签重新打开。

## Migration Plan

1. 本轮只生成本目录规划文档，完成校验后等待用户批准。旧 `terminal-buffer-size` 提案将在本变更归档时作为被取代的未实施提案归档；本轮不修改旧稿。
2. 实施时先收集 macOS 复现证据，按 tasks 的失败测试顺序推进可信状态、事务、表单、iPad 容器与分类清理。
3. 文件格式不变，旧明文仍可读取；只有用户显式启用/更换/移除保护时才进行对应迁移。启用后文件受保护且本次进程已解锁，重启需重新输入保护密码。
4. 提交前失败保留原状态，可修复错误后重试；无需新文件格式回滚。版本回退不得自动移除加密或清空凭据，新版仍输出旧实现兼容的信封。
5. 终端缓冲区配置使用 `UserDefaults` 持久化，非敏感配置，无需钥匙串保护。配置变更后仅新标签生效，已打开终端不受影响。
6. 双端构建、Rust/Swift 测试及覆盖率验收完成后，再申请归档本变更；`terminal-buffer-size` 旧稿随本变更归档一并标记为已弃用。
