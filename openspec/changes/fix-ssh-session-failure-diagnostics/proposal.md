## Why

用户报告交互式 SSH 会话在输入命令后频繁断开，现有日志不足以区分本地发送受阻、远端 shell 退出和传输故障。静态检查已确认错误详情丢失、退出状态被忽略、输入队列暂满触发会话关闭、日志滚动方向错误及文件日志静默失败；这些缺陷可独立修复，但实际断线根因尚未复现，不能把队列满直接认定为事故原因。

## What Changes

- 为 SSH 会话建立安全的结构化诊断：发生阶段、原因类别、错误码、连接与所有者关联、发生时间；在 core、FFI、终端提示和生命周期日志中保留同一原因，清理事件不能覆盖首个具体故障。
- 使同一终端的远端结束与本地关闭只触发一次有效的 Transport 释放；已请求本地关闭后的迟到清理继续被过滤，但尚未确认本地关闭时的具体故障不得被 `Closed` 状态吞掉。
- 隔离会话内部缓冲与后台任务的失败：锁中毒、任务 panic 或句柄关闭失败不得扩散到其他终端，也不得让全局会话表永久不可用。
- 区分正常退出、非零退出码、退出信号、未提供原因的远端关闭、Socket EOF、读写错误、keepalive 失败、本地关闭和后台任务异常；不再仅凭 Channel Close 判定正常退出。
- 为本地输入采用有界、整块接纳的非阻塞接口；队列满返回可恢复的背压结果，界面明确提示本次输入未发送，保持会话存活；真正的传输故障才结束会话，不自动重放输入。
- 生命周期事件在 Rust 中直接进入统一日志，保留事件发生时间，避免依赖 Swift 轮询才写入文件；保留原有非敏感事件查询能力。
- 修复日志列表顺序、稳定条目标识和长消息展示，使最新日志实际可见、原因可完整查看。
- 恢复现行规范要求的 `logs/panda-ssh.log` 路径；旧 `panda.log` 原样保留，文件初始化、写入和轮转失败在内存中可见，日志恢复后继续追加。

## Non-goals

- 不承诺已找到或消除用户环境中的全部断线原因，不把未复现的网络、服务器或后台任务异常当成事实。
- 不引入自动重连、命令重放、会话恢复、端口转发或全局连接池；不改变主机密钥信任和凭据边界。
- 不记录命令、终端输入输出、原始远端错误文本、凭据或完整私钥路径；不全量开启依赖库调试日志。
- 不在本提案创建阶段修改实现、运行真实服务器操作或合并主规格；实现及验证完成后再同步与归档。

## Capabilities

### New Capabilities

无；扩展现有能力。

### Modified Capabilities

- `shell-terminal`：输入背压与接纳语义、终端结束原因、一次性关闭、读写及后台任务故障隔离、正常结束的 UI/工作区状态。
- `runtime-logging`：诊断字段、事件发生时间、直接记录生命周期、日志排序与完整展示、文件路径及持久化失败可观测性。
- `ffi-bridge`：结构化会话终态与背压错误、诊断和日志字段跨语言传递。
- `connection-monitoring`：可恢复背压与真实故障的区别、终态原因和首个故障保留。

## Impact

- Rust：`crates/panda-core/src/ssh.rs`、`telemetry.rs`、`logger.rs` 及错误类型；业务判定、有界队列、关闭状态机、锁恢复和脱敏投影均在 core 实现。
- FFI：`crates/panda-ffi/src/lib.rs` 的 shell 错误、诊断、生命周期和日志记录映射。导出保持同步；网络异步仍使用既有全局 tokio runtime。新增枚举或字段需同步更新 Swift 调用方并重新生成绑定。
- macOS / iPadOS：共用 `TerminalSessionStore`、`TerminalCoordinator`、`Logger` 和 `LogView`，获得一致的故障提示、背压反馈和日志行为；仅配置目录根路径及平台 UI 服务有平台差异。
- 测试：Rust fake 通道、受控本地 fake 服务器、故障注入日志存储与 Swift XCTest；各模块覆盖正常、意外和边界场景，按 red-green-refactor 实施。
- 与 `improve-connection-reliability` 的自动重连规划独立。与 `migrate-business-logic-to-rust` 的日志改动重叠时，保留其 FFI 查询按时间倒序契约，由 UI 展示适配；本提案负责修正已落地实现与当前规范的偏差。
