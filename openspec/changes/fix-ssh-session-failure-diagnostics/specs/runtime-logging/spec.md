## MODIFIED Requirements

### Requirement: 日志条目格式

每条日志 SHALL 包含时间戳、级别、模块名和消息文本。格式 MUST 为 `[ISO8601 时间戳] [级别] [模块] 消息`。文件与 UI 中 MUST 使用相同格式。时间戳 SHALL 表示事件发生时间，而不是 UI 拉取时间；每条日志 MUST 具有进程内稳定且唯一的条目标识，用于相同时间戳下的确定顺序及跨刷新定位。

#### Scenario: 日志条目格式校验

- **WHEN** 记录一条 info 级别、模块为 `SSH`、消息为 `已连接` 的日志
- **THEN** 该条目的文本表示包含 ISO8601 时间戳、`INFO`、`SSH` 和 `已连接` 四个部分

#### Scenario: 延迟拉取与同时间事件

- **WHEN** 多个事件具有相同时间戳，且 UI 延迟拉取或重复拉取
- **THEN** 各事件的原始时间与唯一条目标识保持不变，同时间戳事件按条目标识确定顺序

### Requirement: 文件日志持久化

系统 SHALL 将日志条目追加写入到文件。日志文件路径 MUST 位于应用配置目录下的 `logs/` 子目录（macOS 为 `~/.panda-ssh/logs/panda-ssh.log`，iPadOS 为 App Group 容器内 `logs/panda-ssh.log`）。初始化 SHALL 按需创建 `logs/` 目录。旧版本位于配置目录根的 `panda.log` 及其备份 SHALL 原样保留，不自动删除、截断或合并；新日志仅写规范路径。日志服务早于配置目录就绪时 SHALL 先保留内存日志，并在目录就绪后启用持久化，MUST NOT 因一次未初始化而永久失去文件日志。

#### Scenario: 日志写入文件

- **WHEN** 记录一条日志
- **THEN** 该条目被追加写入到日志文件末尾

#### Scenario: 应用重启后文件继续追加

- **WHEN** 应用重启后记录新日志
- **THEN** 新日志追加到已有文件末尾，不覆盖历史内容

#### Scenario: 首次创建目录与旧文件兼容

- **GIVEN** 配置目录内存在旧 `panda.log`，尚无 `logs/` 目录
- **WHEN** 日志持久化初始化成功并写入新事件
- **THEN** 旧文件内容不变，新事件写入新建的 `logs/panda-ssh.log`

#### Scenario: 日志早于配置初始化

- **WHEN** 先产生内存日志，随后配置目录初始化完成
- **THEN** 后续事件能够持久化，目录就绪前仍保留在内存中的未持久化条目按原有顺序补写且不重复

### Requirement: UI 日志窗口

系统 SHALL 提供一个 UI 窗口展示内存缓冲区中的日志条目。窗口 SHALL 按记录顺序从旧到新排列，最新条目在底部，并 MUST 在新日志到达时自动滚动到底部。重复刷新相同数据 SHALL 保持条目标识、显示顺序和滚动位置。消息 MUST 可完整查看及选择复制，MUST NOT 仅以不可展开的单行截断形式隐藏原因。窗口 MUST 提供清除按钮以清空内存缓冲区。

#### Scenario: 新日志自动滚动

- **WHEN** 日志窗口已打开且缓冲区已满，新日志被记录
- **THEN** 窗口滚动到底部，显示最新的日志条目

#### Scenario: 清除日志

- **WHEN** 用户点击清除按钮
- **THEN** 内存缓冲区被清空，UI 窗口不再显示任何条目（文件内容不受影响）

#### Scenario: 相同数据刷新

- **WHEN** 窗口重复取得同一批日志而没有新增、清除或淘汰
- **THEN** 条目标识不变，不重建整批条目，也不触发自动滚动

#### Scenario: 长错误消息

- **WHEN** 一条诊断消息超出窗口单行宽度
- **THEN** 用户可通过换行展示或展开查看并选择复制完整消息，包括末尾原因字段

### Requirement: SSH 连接生命周期日志

系统 SHALL 为终端、SFTP 和传输拥有的 SSH 连接记录生命周期日志。日志 SHALL 包含 `host:port`、运行时连接标识、非敏感所有者类型与关联标识，并区分连接成功、Channel 正常结束、用户显式关闭、Socket EOF、读写错误、keepalive 失败和用户重试。失败事件 MUST 增加发生阶段、结构化原因类别以及可用的安全错误码；终端结束事件 MUST 保留可用的退出码或安全退出信号类别。无退出原因的远端关闭 SHALL 以 warning 记录，本地输入背压 SHALL 以 warning 记录，真正的传输、任务和异常退出故障 SHALL 以 error 记录。

生命周期事件 SHALL 在产生时进入统一日志，不依赖日志窗口、连接监控窗口是否打开或 UI 是否消费事件；同一事件 MUST NOT 因 UI 拉取被再次写入。已记录日志 SHALL 在会话释放、监控记录移除后仍按既有日志保留策略可查。后续清理 MUST NOT 将原始具体故障降级成通用错误。

日志 MUST NOT 包含命令、终端输入输出、凭据、文件内容、完整私钥路径、原始远端描述或 panic 载荷。错误摘要 SHALL 从允许的类型与数值字段生成，未知类型 SHALL 明示未知，不通过直接输出原始错误字符串补充细节。远端断开原因 SHALL 保留协议数值码，信号仅保留允许的标准类别；未知信号名称不得原样记录。

#### Scenario: exit 正常结束被记录

- **WHEN** 远端 shell 报告零退出码并正常关闭 Channel
- **THEN** 系统记录 info 级 SSH 日志，包含连接标识、终端所有者关联和退出码

#### Scenario: Socket 异常关闭被记录

- **WHEN** Socket 因 EOF、读写错误或 keepalive 连续失败而不可用
- **THEN** 系统记录 error 级 SSH 日志，包含连接标识、主机地址、阶段、原因类别和可用的系统错误码

#### Scenario: 重试建连被记录

- **WHEN** 用户对终端触发重试
- **THEN** 系统记录该标签的新建连代次和新运行时连接标识，且不记录命令或凭据

#### Scenario: 未打开日志窗口且立即释放连接

- **WHEN** 连接失败后立即释放，且 UI 未消费生命周期事件
- **THEN** 统一内存日志已有该故障，文件存储可用时该事件仍被持久化；后续 UI 消费不重复写入

#### Scenario: 错误载荷包含敏感文本

- **WHEN** 故障对象或远端描述包含测试用凭据、命令、输出、路径或任意信号名称
- **THEN** UI、文件日志和诊断查询均不包含这些载荷，只保留允许的类别与数值信息

## ADDED Requirements

### Requirement: 日志持久化失败可观测

日志目录创建、文件打开、追加写入或轮转失败时，系统 SHALL 保留原业务日志于内存，并记录包含失败阶段和安全 I/O 类别的诊断，MUST NOT 静默失败、递归写文件或导致 SSH 会话关闭。重复的同一持久化故障 SHALL 合并或限流，不挤满环形缓冲区。存储恢复后 SHALL 继续追加新日志并记录恢复状态，SHALL 明示失败期间的持久化缺口，不承诺已丢失的历史日志可恢复。轮转失败 MUST NOT 删除当前日志或错误地宣告轮转成功。

#### Scenario: 文件无法写入

- **WHEN** 目录创建、文件打开或追加操作被注入失败
- **THEN** 原日志和持久化失败诊断可在内存中查看，诊断不递归触发文件写入，会话保持原有状态

#### Scenario: 重复失败与恢复

- **WHEN** 相同文件错误连续发生，随后存储恢复
- **THEN** 故障提示被合并或限流，恢复后的新日志正常追加，内存中有恢复及缺口提示

#### Scenario: 轮转失败

- **WHEN** 日志达到轮转阈值但备份重命名失败
- **THEN** 原文件保留，内存报告轮转失败，不清零成功写入量以伪装轮转完成
