## MODIFIED Requirements

### Requirement: 分层会话可观测性

每条传输连接记录 SHALL 独立列出 SSH 会话状态（含 keepalive 结果），以及其尚未释放或最近已结束的 shell、SFTP 与 exec 通道。每条连接 MUST 提供非敏感的所有者类型和关联标识；每个通道记录 MUST 包含通道标识、类型、状态、创建时间、最后活动时间、累计入站/出站逻辑字节数。通道关闭或失败后，记录 MUST 保留到所属连接释放或被新的内存快照策略移除为止，并显示正常结束、显式关闭或异常关闭的最终原因。

shell 发生真实通道或传输写入故障、收到远端关闭或后台任务异常退出时，系统 MUST 在对应终端标签页显示不可交互提示；无输出但未发生失败事件时 MUST 显示为空闲而非异常。本地输入队列满或输入过大 SHALL 作为非致命输入拒绝，MUST NOT 将 Socket、SSH 或 Channel 标记为失败。最终原因 SHALL 与终端及日志一致，保留安全阶段、类别和可用数值码；原因未知的远端关闭 MUST NOT 标成正常结束。清理事件 MUST NOT 覆盖首个具体故障，且只有已确认本地显式关闭的迟到清理可被过滤。连接释放后，最终诊断 SHALL 仍可通过既有日志保留策略查询，无需永久保留监控记录。

#### Scenario: 同一主机的独立所有者连接

- **GIVEN** 同一主机有一个终端标签和一个 SFTP 标签
- **WHEN** 用户查看该连接详情
- **THEN** 页面显示两条底层连接，并分别显示终端与 SFTP 的非敏感所有者关联，MUST NOT 合并为一条连接

#### Scenario: 终端输入失败

- **GIVEN** 终端 shell 的底层通道已经关闭或向其发送数据发生真实故障
- **WHEN** 用户尝试输入或后台任务检测到该故障
- **THEN** 终端标签页立即显示该会话不可交互及可区分的失败状态，且连接监控页同步显示对应 Socket、SSH 会话和通道的已知状态

#### Scenario: shell 正常结束

- **WHEN** 远端 shell 报告零退出码并正常关闭 Channel，且此前没有故障
- **THEN** 监控将该所有者连接标记为正常结束或显式释放，MUST NOT 将同主机其他连接标记为关闭

#### Scenario: 输入暂时无法接纳

- **WHEN** 活跃连接拒绝一次队列满或过大的输入
- **THEN** 监控保留实际已知的连接状态，不产生虚假的 Socket 或 Channel 故障

#### Scenario: 先有具体故障后释放

- **WHEN** 已记录具体读写故障，随后发生通用关闭并释放连接
- **THEN** 释放前快照与日志使用相同的具体故障，释放后该故障仍可在保留期内的日志中查到

#### Scenario: 正常结束状态

- **WHEN** shell 因零退出码正常结束
- **THEN** 终端与工作区显示已结束而非失败，监控记录正常终态与资源释放

#### Scenario: 关闭后发现具体故障

- **WHEN** 未有本地关闭意图的连接先进入 Closed，随后收到具体传输故障
- **THEN** 监控和日志保留该具体故障，而不是仅显示 Closed 或通用清理
