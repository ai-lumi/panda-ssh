## MODIFIED Requirements

### Requirement: 日志条目格式

每条日志 SHALL 包含时间戳、级别、模块名和消息文本。格式 MUST 为 `[ISO8601 时间戳] [级别] [模块] 消息`。文件与 UI 中 MUST 使用相同格式。对应用定义的结构化事件，文件消息 SHALL 使用版本化 canonical JSON 的稳定事件标识与安全参数：顶层键按 `v`、`code`、`params`、`detail` 的顺序，`params` 按参数名升序；所有字符串 MUST 以 JSON 转义后写入一行，禁止原始换行、控制字符和分隔符改变记录边界。非法/重复/不可表示参数或超过单条长度上限的事件 MUST 拒绝写入并记录不含原值的失败诊断，不得截断成貌似有效的事件。UI 消息 SHALL 按当前应用语言呈现事件摘要；相同格式不要求这两类消息文本使用相同自然语言。历史或外部原始诊断 SHALL 原样保留，但仍 MUST 遵守既有敏感信息保护规则。

#### Scenario: 日志条目格式校验

- **WHEN** 记录一条 info 级别、模块为 `SSH`、消息为 `已连接` 的原始文本日志
- **THEN** 该条目的文本表示包含 ISO8601 时间戳、`INFO`、`SSH` 和 `已连接` 四个部分

#### Scenario: 结构化事件区分呈现与落盘

- **WHEN** 应用记录一条 SSH 已连接事件
- **THEN** 文件与 UI 均保留时间、级别、模块和消息四段；文件消息为事件标识与安全参数，UI 消息为当前语言的已连接摘要，两者可通过稳定事件信息关联

#### Scenario: 不可信参数不能伪造日志行

- **WHEN** 结构化事件参数包含换行、方括号、引号或其他控制字符的主机名或路径
- **THEN** 文件只新增一条可解析的日志行，参数按 canonical JSON 转义保存，不能伪造级别、模块或另一条日志记录

#### Scenario: 旧工具与未知结构化版本

- **WHEN** 旧工具只按外层四段读取新结构化事件，或新 UI 遇到未知 `v` 的结构化消息
- **THEN** 旧工具仍取得时间、级别、模块和原始消息字段；新 UI 保留未知消息原文并记录不含敏感值的诊断，不尝试按自然语言或未知 schema 推断事件

### Requirement: UI 日志窗口

系统 SHALL 提供一个 UI 窗口展示内存缓冲区中的日志条目。窗口 MUST 在新日志到达时自动滚动到底部。窗口 MUST 提供清除按钮以清空内存缓冲区。窗口标题、操作、空态、筛选说明及应用定义的日志事件摘要 SHALL 使用当前应用语言；切换语言 SHALL 重新呈现缓冲区中的结构化事件，而不是清空缓冲区或重写文件。历史及外部原始诊断 SHALL 保留原文，不通过自然语言文本匹配尝试反向翻译。

#### Scenario: 新日志自动滚动

- **WHEN** 日志窗口已打开且缓冲区已满，新日志被记录
- **THEN** 窗口滚动到底部，显示最新的日志条目

#### Scenario: 清除日志

- **WHEN** 用户点击清除按钮
- **THEN** 内存缓冲区被清空，UI 窗口不再显示任何条目（文件内容不受影响）

#### Scenario: 切换语言保留日志事实

- **WHEN** 日志缓冲区已有应用结构化事件，用户切换语言
- **THEN** 事件摘要和界面操作使用新语言，条目数量、事件标识、时间戳、级别和安全参数不变，磁盘文件不被重写

#### Scenario: 混合原始诊断与事件

- **WHEN** 缓冲区同时有应用结构化事件与历史或外部原始诊断
- **THEN** 结构化事件按当前语言展示，原始诊断保留原文，应用不对远端或诊断内容进行猜测翻译

## ADDED Requirements

### Requirement: 结构化事件的内存与 FFI 表示

应用结构化日志事件在内存缓冲与 FFI 记录中 SHALL 以结构化消息描述符承载，并与错误消息契约使用同一 wire schema；描述符 SHALL 是呈现的权威来源，消息文本字段仅为持久化与只读外层四段工具的兼容镜像。UI MUST 仅依据描述符呈现结构化事件，MUST NOT 通过解析消息文本或其中的 JSON 恢复事件内容。结构化事件写入 SHALL 经专用事件写入入口执行 schema 校验；非法 descriptor、重复参数、不可表示值或超过固定上限的事件 MUST 拒绝写入，并以登记于消息清单的固定拒绝事件标识记录不含被拒原值的诊断。单条结构化事件消息字段的长度上限 MUST 是随实现提交的固定公开常量，运行时 MUST NOT 可变；既有原始文本写入入口与既有日志记录字段形状 MUST 保留。

#### Scenario: 描述符为呈现权威

- **WHEN** UI 展示缓冲区中的结构化事件并切换语言
- **THEN** 摘要由描述符与当前语言资源生成，不需要解析消息文本字段或其中 JSON，混合的原始诊断保持原文

#### Scenario: 超限与非法事件被拒绝

- **WHEN** 事件序列化后超过固定上限常量，或描述符存在重复参数、tag 与值不一致
- **THEN** 事件被拒绝写入，记录携带固定拒绝标识、拒绝原因与上限数值且不含被拒原文的诊断事件，内存缓冲与文件不出现貌似有效的事件

### Requirement: 应用日志事件的本地化资源

应用维护且用作用户提示的日志事件摘要 SHALL 以稳定消息标识与安全参数记录，并具有完整中英资源。异常信息原文、底层依赖库错误、远端返回与用户输入无需翻译；纯开发诊断可以保留原始技术文本，但 MUST NOT 将程序自行定义的 Rust/FFI 错误说明归为原始诊断以绕过双语资源要求。语言切换 MUST NOT 改变日志级别、模块标识、环形缓冲容量、文件轮转、写入顺序或安全边界。

#### Scenario: 用户可见日志摘要完整翻译

- **WHEN** 应用记录连接生命周期、传输失败或配置操作结果等用户可见事件
- **THEN** 中英界面均可通过资源呈现摘要，参数仅包含既有日志规范允许的上下文，不含命令、终端输出、凭据或文件内容

#### Scenario: 文件输出不随界面语言漂移

- **WHEN** 同一个事件及相同参数分别在中文和英语模式下被记录
- **THEN** 除各次实际时间和运行时标识外，文件事件表示保持同一语言无关规则，UI 使用对应语言资源
