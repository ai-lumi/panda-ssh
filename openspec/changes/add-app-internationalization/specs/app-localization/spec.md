## Purpose

统一 Panda SSH 在 macOS 与 iPadOS 上的用户可见提示资源，提供完整、含义一致的简体中文和英语呈现，并确保动态参数、安全信息与用户原始数据在国际化过程中不被误译或破坏。

## ADDED Requirements

### Requirement: 全量提示性文案资源化

系统 SHALL 将所有应用维护的提示性文本从实现代码抽取到国际化资源，范围 MUST 包含页面/窗口标题、导航、菜单、按钮、表单、占位符、空态、帮助、无障碍描述、确认框、Toast、状态标签、校验错误、连接/传输/凭据错误和应用日志事件摘要。程序自身定义的全部 Rust/FFI 错误说明 MUST 纳入双语资源，不论目前是否存在可达的 UI 路径；异常原文与底层依赖库返回的错误不属于这些自定义说明。系统 MUST 同时覆盖 macOS 与 iPadOS、Swift 与 Rust/FFI 文本来源、正常路径与失败路径，不得只处理含汉字的字符串。既有规范中的中文按钮或提示引用 SHALL 表示中文版本及其语义，英语版本 MUST 保持相同动作和安全含义。

#### Scenario: 两端同一动作的完整翻译

- **WHEN** 用户分别以简体中文与英语打开主机、分组、片段、终端、SFTP、传输、监控、日志及设置页面
- **THEN** 各页面的应用维护文案使用当前语言对应资源，包括上下文菜单、工具提示和无障碍描述，不混入另一语言的遗留提示

#### Scenario: 异常提示也来自资源

- **WHEN** 用户触发连接失败、文件操作失败、凭据保护失败或配置导入失败
- **THEN** 错误标题、应用维护的原因说明及建议操作均使用当前语言，而不是直接展示内部错误枚举名或固定语言错误串

#### Scenario: 仅一个平台具有的提示

- **WHEN** 用户打开 macOS 原生右键菜单或 iPadOS 独有的操作入口
- **THEN** 应用设置的标题、说明和动作均有双语资源，不因代码位于平台分支而遗漏

### Requirement: 双语翻译完整性与语义一致性

每个用户可见资源 SHALL 具备非空、已完成的 `zh-Hans` 和 `en` 译文；所有被使用的复数或设备变体 MUST 同样完整。资源键 MUST 独立于显示文本，纯文案调整不得改变动作标识或持久化数据。认证失败、主机密钥变更、凭据明文保存、覆盖与删除等安全提示 MUST 在两种语言中保留风险、对象和确认含义。

#### Scenario: 交付前校验所有资源

- **WHEN** 对交付资源执行完整性检查
- **THEN** 两种语言的全部有效键和必要变体均有完成译文，没有空译文、待翻译占位文本或未解析键

#### Scenario: 英语主机密钥变更告警

- **WHEN** 英语模式下服务器密钥与已存储密钥不一致
- **THEN** 告警说明密钥变更及潜在中间人攻击风险，呈现原始指纹，保持阻断连接的既有行为

### Requirement: 参数与复数按完整消息本地化

系统 SHALL 以完整句子模板和具名语义参数表达动态提示，不通过拼接已翻译片段形成句子。中英模板 MUST 保持参数数量、类型和语义一致，允许译文调整参数顺序；数量为 0、1 和多个时 MUST 使用正确的英语复数形式与自然的中文表达。显示用数量、时长等 MUST 使用所选语言对应的格式规则，不改变实际计算值、协议数据或机器可读格式。动态消息标识（如 Rust/FFI 描述符 code）的复数与格式变体 SHALL 通过经验证的公开 API 路径触发，该路径 MUST 覆盖显式语言选择、动态键查找、0/1/多数量变体与参数类型不符行为，并在实施任何依赖它的迁移前以 macOS 与 iPadOS 测试验证；验证不通过 MUST 先修订本能力的资源格式或解析器方案，MUST NOT 在实施中临时决定。

#### Scenario: 数量边界

- **WHEN** 传输提示分别包含 0、1、2 个文件以及可表示的大数量
- **THEN** 英语使用正确单复数，中文表达自然，数量不溢出、不截断，模板占位符不会直接显示

#### Scenario: 动态键复数变体经预先验证

- **WHEN** 呈现层以动态消息标识渲染 0、1 与多个数量的消息，且系统语言与目标语言相反
- **THEN** 经验证的公开 API 路径按显式选择的语言返回正确复数变体；参数类型不符时返回通用错误资源而非显示占位符

#### Scenario: 动态参数原样保留

- **WHEN** 主机名或路径包含中文、英文、百分号、花括号、引号或换行
- **THEN** 参数作为数据安全插入模板，不被二次解释为资源键或格式字符串，不引发格式化失败

### Requirement: 翻译范围与原文边界

系统 MUST NOT 翻译或改写用户输入、主机/分组/片段名称、命令、远端输出、文件名、路径、指纹、协议标识或配置键。异常信息原文（含异常链、堆栈）、底层依赖库返回的错误及操作系统原始诊断无需翻译，按原有安全策略作为技术详情保留；应用自行添加的概括说明、上下文前缀和恢复建议 MUST 使用资源，MUST NOT 将这些自定义文案混在原文中逃避翻译。应用维护的默认占位文案和示例界面说明 SHALL 本地化，但已经保存为用户数据的值 MUST 保留。

#### Scenario: 英语界面展示中文远端文件名

- **WHEN** 英语界面列出远端文件 `备份.tar`，或终端收到中文输出
- **THEN** 文件名及终端内容原样展示，只有应用自身的按钮和提示使用英语

#### Scenario: 外部错误没有可用分类

- **WHEN** 外部错误无法映射到已知类别
- **THEN** 系统显示本地化的通用失败说明，必要技术详情与说明分离，详情不包含密码、口令、保护密钥、私钥内容或禁止披露的私钥完整路径

### Requirement: 资源回退与遗漏门禁

运行时当前语言缺少某个资源时，系统 SHALL 回退到该消息的简体中文译文；键未知或简体中文也不可用时 SHALL 显示随应用内置的简体中文通用错误资源，不崩溃、不直接泄露资源键。回退仅用于容错，资源遗漏、参数不匹配或未抽取的提示 MUST 阻止交付通过完整性门禁。检查 MUST 同时覆盖中文、英文和动态拼接来源，排除项 MUST 有可审查的用途说明，不能以“非中文”或整个业务目录作为排除理由；异常或依赖原文的排除不得涵盖程序自行添加的说明。文案门禁 MUST 由受版本控制的提示清单、逐条排除清单和 CI 审计命令共同执行：生产 Swift 提示只能经批准的资源入口创建，生产 Rust/FFI 固定用户说明只能引用消息标识；新增扫描命中、缺少清单条目、资源/参数模式漂移或不合格排除均 MUST 失败。

#### Scenario: 当前语言资源缺失

- **WHEN** 测试故意移除某条英语译文
- **THEN** 运行时显示简体中文回退且记录不含敏感信息的诊断，资源检查失败

#### Scenario: 未知消息或格式不匹配

- **WHEN** 消息键不存在或参数与模板不兼容
- **THEN** 用户得到通用可读错误提示，应用不崩溃、不显示原始键或格式占位符，对应测试及资源门禁失败

#### Scenario: 新增硬编码英语提示

- **WHEN** 开发者在生产提示路径新增未资源化的英语或中文字符串
- **THEN** 文案审计将其报告为遗漏，只有明确属于原始数据或纯诊断的条目才可按可审查规则排除

### Requirement: 并行变更的提示契约

所有活动 OpenSpec 变更新增或修改应用维护的提示性文本时 SHALL 遵守本能力的资源、键命名、双语完成和审计契约。变更作者 MUST 在合并前将提示登记到清单，并选择唯一的 `Localizable` 或 `Messages` 所有者；Rust/FFI 来源的提示 MUST 使用 message code。冲突 SHALL 以本能力的已评审资源契约为准，不得通过在其他 change 内保留硬编码文本绕开审计。

#### Scenario: 并行变更新增连接提示

- **WHEN** 另一个活动变更为连接或传输增加应用维护的失败提示
- **THEN** 该提示具有唯一资源所有者、完整中英译文和清单条目，并通过 `scripts/check-localization-completeness`
