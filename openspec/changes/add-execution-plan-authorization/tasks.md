# 任务：执行计划与授权生命周期

约定：每个功能任务先写失败测试（TDD red），再实现到全绿（green），再重构；任务粒度为一次可验证提交。测试任务显式覆盖三类场景——正常流程、意外操作、边界条件。本提案不含真实命令执行器与审计实现（分别由 add-batch-remote-execution / add-command-audit-trail 交付），一律以 fake 注入测试。

## 1. 计划数据模型与内容冻结（crates/panda-core）

- [ ] 1.1 测试先行：新建 `plans` 模块的测试骨架——计划记录最小字段集与展开校验（目标必须为具体主机 ID；正常：全字段计划可构建且序列化往返一致；意外：目标含分组引用/缺凭据引用/缺资源预算被拒绝；边界：空跳板链、无引用列表、单目标、超长命令字段）；内容哈希（正常：同一计划规范化序列化后哈希可复现且与字段顺序无关；意外：任一字节变化产生不同哈希；边界：空命令、同哈希内容须不可构造出实际差异用例）；引用冻结（正常：引用片段保存快照 + 内容哈希；意外：引用源内容变更后「源哈希 == 冻结哈希」比对返回不一致；边界：引用被删除、快照自身重算哈希等于冻结哈希的自校验）；计划与运行记录不含密钥材料（序列化输出断言无秘密字段）。
- [ ] 1.2 实现：`ExecutionPlan` 记录结构（目标集合、身份引用、跳板链、逐目标命令与展开参数、引用快照与哈希、环境前提、验证步骤、资源预算、数据流向）、规范化序列化 + SHA-256 内容哈希、引用冻结与执行前比对函数；不落盘（存储在任务 2）。

## 2. 计划存储与生命周期状态迁移（crates/panda-core）

- [ ] 2.1 测试先行：`plans.toml` 存储读写（正常：保存后读回等价、追加批准记录有序可读；意外：损坏 TOML 返回可区分错误且不覆盖原文件、对不存在文件首次写入创建目录；边界：空文件、重复保存同一 id 幂等、原子写不留临时文件）；生命周期迁移表（正常：草稿→待审核→已批准→执行中→已完成全链路；意外：草稿直接执行、已失效/已撤销再批准、执行中再启动新运行均被拒绝且状态不变；边界：已完成计划重新批准生成新批准记录同哈希、终态不可迁出）。
- [ ] 2.2 实现：TOML 持久化（复用 `write_atomic`）+ 纯函数状态迁移 `transition(plan_state, event)`；批准记录结构 `{plan_id, content_hash, approved_at, expires_at}` 追加语义。

## 3. 授权判定与失效规则（crates/panda-core）

- [ ] 3.1 测试先行：授权判定纯函数（正常：有效批准 + 哈希一致 + 未过期 → 授权通过；意外：批准哈希 ≠ 计划哈希、批准已撤销、已过期、目标集合与批准版本不一致、身份或跳板路径与批准版本不一致均判失效并返回可区分原因；边界：`expires_at = None` 永不过期、恰在过期时刻判失效、无法完成检查（引用源不可读/主机配置缺失）时按「无法确认即在范围内」停止）。
- [ ] 3.2 实现：授权判定函数与失效原因枚举；判定输入全部显式注入（时钟、计划、批准记录、当前配置快照），保证可测。

## 4. 九态运行状态机（crates/panda-core）

- [ ] 4.1 测试先行：迁移表全查（正常：等待批准→排队→运行→成功、排队→运行→超时等合法路径逐一遍历；意外：成功/失败/终态迁出、运行直接迁到已确认停止等非法迁移被拒绝；边界：取消请求→已确认停止、运行→结果未知、取消请求→结果未知；「未收到退出码不得置成功」与「停止等待 ≠ 远端已停止」的守护断言）。
- [ ] 4.2 实现：九态枚举 + 常量迁移表 + 纯函数校验；运行记录结构（run_id、plan_id、逐目标步骤状态取同一九态词汇）。

## 5. 统一执行网关与执行器接口（crates/panda-core）

- [ ] 5.1 测试先行：以 fake `PlanExecutor`（记录调用与发出目标）、fake `AuditSink`（可注入预检失败/写入失败）、临时目录 known_hosts 构建网关测试——校验顺序与拒绝（正常：全链路通过后执行器收到冻结计划快照且 run_id 返回；意外：未批准/已撤销/已过期/引用变化/审计不可用分别返回可区分错误且执行器调用次数为 0、未建立任何连接；边界：撤销后剩余目标不再发起、已发出步骤结果未知保留、部分成功不汇总为全部成功、连接期 `HostKeyMismatch` 使计划失效并停止后续目标）。
- [ ] 5.2 实现：`ExecutionGateway::start` 校验编排（状态 → 授权 → 引用比对 → 主机密钥文件级预检 → 审计可用性）+ `PlanExecutor` / `AuditSink` trait 定义 + 运行记录落盘（`plan_runs.toml`，迁移时更新）；异步执行挂既有全局 runtime 语义由 FFI 层承载（任务 7），core 只暴露同步接口。

## 6. 主机密钥前置检查联动（crates/panda-core）

- [ ] 6.1 测试先行：网关对逐目标与逐级跳板的 known_hosts 文件级检查（正常：全部 Known → 放行；意外：任一目标 Unknown → 拒绝且错误指明该主机、known_hosts 未被写入、不触发 TOFU；边界：跳板链为空跳过跳板检查、同主机多 keytype 任一记录即视为已知、端口非 22 的 `[host]:port` 令牌匹配）。
- [ ] 6.2 实现：在网关校验编排中接入 `KnownHosts::status()`；「主机密钥未验证」错误携带主机与状态。

## 7. FFI 导出与错误分类（crates/panda-ffi）

- [ ] 7.1 测试先行：新导出的行为测试（正常：创建→提交→批准→启动返回 run_id→查询状态→停止全流程可达，启动在网关校验后快速返回不等待远端；意外：未初始化返回 `NotInitialized`、未批准/失效/引用变化分别返回对应结构化错误变体而非 `Core(String)`；边界：未知 plan_id/run_id 可区分、批准消耗后二次启动被拒、计划与审计序列化中无瞬态凭据参数痕迹）。
- [ ] 7.2 实现：同步导出 `create_execution_plan` / `get_execution_plan` / `list_execution_plans` / `submit_execution_plan` / `approve_execution_plan` / `reject_execution_plan` / `revoke_execution_plan` / `pause_execution_plan` / `start_execution_plan_run` / `get_execution_run_status` / `request_execution_run_stop`，`PandaError` 新增变体；异步执行在懒初始化全局 tokio runtime 上 `block_on` 启动后立即返回；不改动任何既有导出签名。
