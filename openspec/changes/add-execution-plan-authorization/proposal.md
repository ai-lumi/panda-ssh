# 执行计划与授权生命周期（Execution Plan & Authorization）

> 关联路线图：brainstorming-ai-era-roadmap.md 第四章（4.1/4.2）、8.6「执行与授权」「长任务」、11.4 推荐架构、13.1 三条执行主线、待决 #34（原则已决、待设计）。
> 本提案是「首个纵向闭环」四个并行提案之一：与 add-command-audit-trail（审计）、add-batch-remote-execution（批量执行）、add-manual-inspection-loop（人工巡检）共享同一套词汇与契约，并为其提供授权基座。

## Why

路线图 4.2 已决：审批对象是具体执行计划及其确定范围，而不是抽象 Skill 名称或宽泛命令模式。当前代码没有任何计划、审批或授权概念：系统代发的远程操作（批量执行、巡检、未来的 MCP/定时）没有统一的执行前强制检查点，无法保证「生成、审核、执行针对同一版本」，也无法在目标、内容、身份、跳板路径变化或授权撤销后阻止旧授权被复用。本提案把「可校验计划 → 人工审核与授权 → Rust 执行/验证/审计」（路线图 11.4）中的计划与授权环节落成规格，供批量执行与巡检提案消费。

## What Changes

- 新增执行计划（Execution Plan）数据模型：至少含目标主机集合（展开为具体主机 ID）、身份（凭据引用）、跳板链、命令与展开后参数、引用片段/方案的内容版本标识、环境前提、验证步骤、资源预算（并发/输出上限/时长）、数据流向；计划不含任何密钥材料。
- 新增计划内容冻结与版本绑定机制：计划以内容哈希标识版本，引用片段/方案在审核时冻结快照与哈希，执行前做变化检查。
- 新增计划生命周期：草稿 → 待审核 → 已批准 → 执行中 → 已完成/已失效/已撤销；审批绑定计划版本，一次性批准仅覆盖该次计划。
- 新增授权失效规则：目标集合变化、内容更新、身份或跳板路径变化、授权撤销/过期、主机密钥异常，均使旧授权失效，失效后不得复用。
- 新增 Rust 统一执行网关（panda-core）：所有系统代发远程操作（供批量执行/巡检/未来 MCP 复用）在执行前强制校验计划版本、范围、授权状态、主机密钥状态与审计可用性；校验失败以可区分错误拒绝。UI 展示或模型自律不能替代执行前检查。
- 新增执行运行状态机（九态：排队、等待批准、运行、成功、失败、超时、取消请求、已确认停止、结果未知），供本提案与批量执行/巡检提案共用；停止等待 ≠ 远端已停止，未收到退出码不得默认成功。
- 新增撤销与暂停语义：用户可暂停/撤销；撤销后不得新发起步骤；已发出操作的停止结果如实记录（结果未知保留）。
- 新增学习/AI 不可扩权约束：模型、Skill、记忆、远端输出不得签发授权、扩大范围、降低确认要求或修改审批状态/审计记录。
- 明确与手动终端的边界：手动输入本身是该次操作指令，本提案不引入逐键审批。
- 新增计划审核 UI（SwiftUI）：逐目标命令、身份、数据流向、预算、验证步骤预览 → 确认/拒绝；panda-ffi 同步导出对应契约与结构化错误。

## Capabilities

### New Capabilities

- `execution-authorization`：执行计划数据模型与冻结、计划生命周期与审批绑定、授权失效规则、Rust 统一执行网关强制检查、九态执行状态机、撤销与暂停、学习/AI 不可扩权、手动终端边界、审计联动阻断、凭据隔离（凭据引用 + 连接层按授权使用）。

### Modified Capabilities

- `ffi-bridge`：新增「执行计划 FFI 契约」需求——计划/审批/撤销/执行/状态查询的同步导出接口与结构化错误（授权失效、计划过期、主机密钥未验证等可区分错误）；异步工作仍在既有全局 tokio runtime 上执行。现有连接入口（`test_connection`、`shell_open`、`sftp_*`）的手动路径语义不变。

## Impact

- `crates/panda-core`：新增执行计划存储（计划与授权记录持久化于配置目录 TOML）、内容哈希与冻结、授权失效判定、执行网关、九态运行状态机；与 `KnownHosts`（hostkey.rs）三态判定联动，与审计能力通过接口衔接（具体审计实现来自 add-command-audit-trail）。
- `crates/panda-ffi`：新增计划管理/执行/查询同步导出与 `PandaError` 新变体；导出类型仅用简单值类型（Record/Enum/Option），密钥材料仍只作瞬态参数传入、不经 FFI 落盘。
- `apple/PandaSSH`：新增计划审核界面与状态展示；Swift 仅做 UI 与钥匙串等平台服务，业务规则全部经 FFI 调用。
- 跨提案契约：批量执行提案经网关发起执行并提供真实命令执行器；巡检提案复用计划与九态状态机；审计提案提供审计记录实现（本提案只依赖「审计写入失败或完整性无法核验时阻断新步骤」的语义）；add-ssh-proxy-jump 提案提供跳板链字段（本提案只引用其字段，不实现跳板）；凭据存储基线由 resolve-baseline-conflicts 提案消解，本提案涉及凭据时统一表述为「凭据引用（*_ref）+ 连接层按授权使用」。

## Non-goals

- macOS 定时巡检的周期授权与准入流程（4.3，Phase 2 单独提案）。
- MCP 工具暴露与适配层（后续提案；本提案只保证其未来必须过网关）。
- AI 候选计划生成（薄 AI 增益实验后续；本提案只约束「学习/AI 不可扩权」）。
- 跳板机连接实现本身（仅引用 add-ssh-proxy-jump 提案的跳板链字段）。
- 凭据存储架构变更（由 resolve-baseline-conflicts 提案消解基线）。
- 批量命令的真实执行器与并发/输出预算的执行侧强制（由 add-batch-remote-execution 提案实现；本提案只定义网关校验、九态状态机与执行器接口语义）。

## 双端影响（macOS / iPadOS）

- 计划的生成、审核（预览/确认/拒绝）、撤销与状态展示在双端均可用；授权网关校验逻辑全部在 panda-core，双端行为一致。
- iPadOS 支持人工触发的一次性计划执行（人在线审核与触发），不支持也不展示定时执行；定时周期授权属 Phase 2 且仅 macOS，本提案不引入任何定时能力，双端均无后台代发。
- 平台条件编译仅限 UI 与平台服务差异（如窗口尺寸、键盘类型）；授权规则、状态机、失效判定不得出现 `#if os()` 分支。
