## ADDED Requirements

### Requirement: 断开后终端上下文保留

当已建立 shell 的终端因正常退出、异常断开或未知远端关闭进入终态时，系统 SHALL 保留该终端在终态前已接收的输出与可滚动上下文。终态后输入 MUST 立即不可用，系统 MUST NOT 自动重连、重放任何已接纳但交付状态未知的输入，且不得将已关闭句柄用于读取或写入。

终端画布 SHALL 在保留的输出之后显示本地终态提示和手动重新连接入口。提示 MUST 使用与日志和监控一致的安全结构化原因：正常退出可显示退出码，异常终态可显示白名单类别、阶段及可用数值码；未知原因 MUST 明示未知。提示 MUST NOT 直接包含原始远端描述、终端输出、命令、凭据、完整私钥路径或 panic 载荷。正常结束和异常断开均 SHALL 将所属标签标记为已断开/失败；正常结束不得被错误地描述为连接仍可交互。

#### Scenario: 正常退出后保留终端输出

- **GIVEN** 终端已收到多行输出
- **WHEN** 远端 shell 报告退出码 0、输出排空并关闭
- **THEN** 已收到的输出仍可滚动查看，输入不可用
- **AND** 终端尾部显示正常结束与退出码 0 以及手动重新连接入口

#### Scenario: 异常断开后保留安全原因

- **GIVEN** 终端已收到输出
- **WHEN** Transport 发生已确认的读取错误并带有安全系统错误码
- **THEN** 已收到的输出仍可滚动查看，输入不可用
- **AND** 终端尾部显示读取错误类别和该数值码，不显示任意原始异常字符串

#### Scenario: 未知远端关闭

- **WHEN** shell Channel 关闭而没有退出码、退出信号或更具体的故障证据
- **THEN** 已收到输出保持可见，终端尾部显示“远端会话已关闭，原因未知”与手动重新连接入口

#### Scenario: 手动重新连接不重放输入

- **GIVEN** 终端已在断开后显示重新连接入口
- **WHEN** 用户点击重新连接
- **THEN** 系统创建一个新连接代次并仅在成功后恢复输入
- **AND** 系统不重放旧会话中交付状态未知的任何输入
