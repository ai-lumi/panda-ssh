# 设计：保留断开会话的标签页上下文

## Context

当前 `TerminalTabView` 在 `.failed` 或 `.ended` 时以居中状态面板替换 `SwiftTermWrapper`；`TerminalSessionStore` 对读循环异常仅保存泛化文本。`SftpTabView` 在已连接后的目录读取失败也会进入 `.failed`，以 `ConnectFailureView` 替换双栏浏览器。

本提案只改变“已建立后终止”的呈现与状态映射。初次连接、凭据输入和 TOFU 门控失败仍以现有错误页处理，避免把从未可用的内容伪装成可恢复快照。

## Goals / Non-goals

**Goals:**

- 保留用户可见的 SSH 终端输出与 SFTP 浏览快照。
- 用一致、可操作、无敏感载荷的终态原因解释断开。
- 用标签红色状态同时让非活动标签的失败可见。
- 严格区分 SFTP 会话失效与单次远程文件业务错误。

**Non-goals:**

- 不自动建立新连接，不恢复 shell 进程，也不重放任何不确定是否送达的输入或传输。
- 不将 Swift `localizedDescription`、远端错误字符串或日志原文作为“原始原因”直接渲染。

## State model

终端与 SFTP 各自维护“是否曾经可用”的状态；终态由 core/FFI 的安全原因驱动：

| 标签类型 | 初次建连失败 | 已建立后正常结束 | 已建立后异常断开 | 用户关闭标签 |
| --- | --- | --- | --- | --- |
| SSH | 错误页；状态失败 | 保留终端；输入禁用；追加正常结束原因；红色图标 | 保留终端；输入禁用；追加故障原因；红色图标 | 移除标签并精确关闭会话 |
| SFTP | 错误页；状态失败 | 不适用（SFTP 无 shell exit） | 保留浏览快照；远程操作禁用或明确拒绝；红色图标 | 移除标签并精确关闭会话 |

“已建立”指终端已获得 shell，或 SFTP 已成功读取初始远程目录快照。若失败发生在此之前，仍属于初次建连失败。

## Decisions

### 1. SSH 以终端内尾注呈现最终状态

终端模拟器保留已接收输出。断开后不得再挂载读循环或接收输入；视图在该画布底部以与普通输出可区分的本地尾注追加：会话结束类别、可用安全数值、以及“重新连接”按钮。按钮创建新连接代次，绝不复用已关闭的句柄。

尾注使用来自结构化终态的白名单投影。例如可显示“SSH Transport 已断开（读取错误，系统码 54）”或“远端 shell 已结束（退出码 1）”；未知原因明确显示未知。不得显示任意 `Error.localizedDescription` 或远端提供的自由文本。

### 2. SFTP 保留只读快照，而非伪装为在线浏览器

断开前成功提交的本地与远程目录快照、当前路径和选中状态保留。会话级断开后，依赖远程句柄的导航、刷新、创建、删除、冲突检查和新传输操作必须在调用 FFI 前拒绝或由统一入口返回“会话已断开”；不得尝试使用失效句柄。

本地文件浏览仍可查看；为避免用户误以为远程文件操作可用，远程面板应有非阻塞的断开状态提示与“重新连接”入口。重新连接成功后以当前远程路径优先刷新；路径不再可访问时回退根目录并按既有错误提示处理。

### 3. SFTP 断开判定收敛在会话边界

只在底层 Transport/会话句柄已关闭、被明确标记不可用，或 FFI 返回结构化“会话不可用”类别时，将标签转为红色断开状态。权限拒绝、文件不存在、目录语义错误、覆盖冲突、单项传输失败等仍由各操作现有错误路径报告，标签保留已连接状态。

若现有 FFI 无法给出该边界，新增最小枚举或状态查询，而不是在 Swift 通过错误字符串猜测。该工作与 `fix-ssh-session-failure-diagnostics` 的原因分类共同设计，防止两套分类漂移。

### 4. 标签与侧栏状态

`WorkspaceConnectionStatus.failed` 继续代表本标签不可用，标签图标以红色呈现。侧栏仍按既有聚合规则：同主机另有连接中或已连接标签时保持可达；否则显示无可用会话。红色是标签状态而非主机密钥或单次业务操作状态。

## Testing strategy

先写失败测试，再实施最小代码：

1. 终端正常/异常/未知结束后保留缓存输出，尾注原因符合白名单，输入不可用、红色标签状态正确，重连只创建一个新代次。
2. SFTP 初次建连失败仍为错误页；建立后会话失效时保留双栏快照并标红；同一主机其他标签与后台传输不受影响。
3. SFTP 权限、路径和冲突错误不标红、不替换浏览器；失效句柄路径不再发起远程 FFI 操作。
4. 边界覆盖迟到回调、重复断开、用户关闭与断开竞争、旧连接代次回调、重连时当前目录不存在。

Rust/FFI 涉及新状态时用 fake 会话测试；Swift 以可注入 fake 验证 UI 状态机。完成后执行既有 Rust 覆盖率门禁、相关 Swift XCTest 与 macOS/iPadOS 构建，并用受控 fake 服务器手动检查呈现。

## Risks / Trade-offs

- [假设] 保留终端画布需要终端组件支持独立的本地尾注层；若无法直接注入文本，采用画布叠层，但仍不得遮挡已有滚动内容。
- 用户可能把红色理解为永久故障，因此必须配合明确的、手动触发的重新连接入口。
- 保留 SFTP 快照可能过时；断开提示必须明确它是断开前快照，重新连接后才刷新远程事实。
- 依赖未完成的诊断提案；若其终态结构变更，本提案必须同步复用其最终公共契约。
