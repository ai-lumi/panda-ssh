## MODIFIED Requirements

### Requirement: 标签页会话关联

每个标签页 SHALL 基于一台已保存主机建立并独占其服务器会话，核心 SHALL 管理该关联及精确释放。关闭标签 SHALL 仅关闭该标签拥有的 Channel 和 Transport；同主机其他标签与独立传输任务 MUST NOT 受到影响。传输 SHALL 在自身终态释放其连接，不再以“关闭主机全部连接”或“为传输保留标签连接”实现生命周期。远端 shell 正常退出或关闭时，终端标签 SHALL 在呈现退出前已接收的全部输出后更新为断开状态并释放对应会话，其余会话继续运行。

#### Scenario: 标签页基于已保存主机打开

- **WHEN** 用户从主机列表选择一台主机打开标签页
- **THEN** 核心使用该主机的地址、端口、用户名与认证方式为新标签建立独立会话

#### Scenario: 关闭最后一个标签页立即断开

- **GIVEN** 某主机只有一个标签页且无活跃传输任务
- **WHEN** 用户关闭该标签页
- **THEN** 核心立即释放该标签的会话和 SSH 连接

#### Scenario: 关闭 SFTP 标签时独立传输继续

- **GIVEN** 某主机最后一个 SFTP 标签创建了 running 或 queued 传输任务
- **WHEN** 用户关闭该标签
- **THEN** 核心立即关闭标签拥有的连接，传输使用自身连接和凭据继续运行或排队
- **AND** 各传输在自身终态释放其连接

#### Scenario: 终端 shell 正常退出

- **GIVEN** 某终端标签已连接且远端 shell 在输出结束信息后正常退出
- **WHEN** 客户端读完退出前产生的全部输出
- **THEN** 核心将对应会话更新为已断开，该标签显示断开状态，关闭时不再要求已连接会话确认

#### Scenario: 退出的是最后一个主机会话

- **GIVEN** 某主机只有一个已连接终端标签，且无其他会话或活跃传输
- **WHEN** 该终端 shell 正常退出
- **THEN** 核心释放该 shell 会话和其 SSH 连接

#### Scenario: 同主机仍有会话或传输

- **GIVEN** 某终端 shell 正常退出，但同主机仍有其他会话或活跃传输
- **WHEN** 核心处理退出
- **THEN** 仅释放退出会话的资源，其他所有者的连接保持有效

## ADDED Requirements

### Requirement: 工作区逻辑状态由核心统一管理

核心 SHALL 统一拥有标签身份、逻辑顺序、活动标签、标题分配、分组关系、连接状态聚合和关闭请求状态。Swift 与 FFI MUST NOT 持有独立改变这些事实的第二套状态机。工作区命令 SHALL 返回可呈现结果；界面只提交选择、逻辑移动、关闭和确认动作，几何布局与原生呈现不进入核心。

#### Scenario: 排序后关闭活动标签

- **GIVEN** 用户已调整标签顺序或分组
- **WHEN** 关闭活动标签
- **THEN** 核心按当前逻辑顺序应用相邻标签选择规则，其他标签标题与会话保持不变，UI 无需在另一顺序数组补算

#### Scenario: 已连接终端关闭确认

- **WHEN** 请求关闭已连接终端或包含已连接终端的标签范围
- **THEN** 核心返回关联目标与数量的待确认结果，UI 只展示弹窗；取消保留会话，确认后核心执行精确关闭
- **AND** UI 不通过先将连接状态改成 inactive 来绕过核心确认判断

#### Scenario: 确认期间目标变化

- **WHEN** 确认返回前目标标签已关闭、断开或创建了新会话代次
- **THEN** 核心验证请求目标及代次，不关闭未被该确认授权的新会话，不恢复已关闭标签

#### Scenario: 不存在的标签与空工作区

- **WHEN** 请求选择/关闭不存在的标签或关闭空工作区
- **THEN** 核心按既有接口约定返回无操作或明确结果，状态保持自洽，其他会话不受影响
