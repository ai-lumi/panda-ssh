# 提案：业务逻辑归属 panda-core，FFI 收敛为薄桥

## Why

当前业务逻辑虽已大量迁入 Rust，但传输调度、工作区状态、凭据编排等仍由 `panda-ffi` 或 Swift 持有，仅依赖 `panda-core` 的新前端无法复用完整应用能力。需要把“Rust 实现”进一步约束为“`panda-core` 拥有业务规则和执行流程”，让 FFI 成为可替换的跨语言适配层。

## What Changes

- 在 `panda-core` 内建立可直接调用的应用服务入口及按领域组织的服务，统一拥有业务状态、校验、流程编排、持久化策略和资源生命周期；核心允许有状态及异步 I/O，不限于纯算法。
- 下沉单文件/批量传输注册表、调度、暂停/继续/重试、冲突处理、删除与未完成任务管理；保留现有任务语义和源标签关闭后的独立生命周期。
- 下沉主机与凭据联合保存/删除、失败补偿、引用规则、凭据选择、连接前评估、TOFU 等待者协调，以及会话重试代次与迟到结果清理。
- 下沉工作区逻辑状态，包括标签身份、逻辑顺序、分组关系、标题、关闭确认判断与会话关联；Swift 保留几何布局、焦点、拖拽手势、原生弹窗和其他纯呈现状态。
- FFI 仅保留类型/错误转换、同步到异步运行时适配、核心入口装配和必要的跨语言句柄/消息投递。确需较厚的适配必须登记具体技术限制、状态边界和测试；业务方便性不构成例外理由。
- 增加可证伪的架构验收：无 UI、无 UniFFI 的核心宿主复用完整业务流程；同一场景在核心与 FFI 路径结果一致；生产调用方不再维护重复业务状态机。
- 对齐 FFI 模块边界与覆盖率规则，使门禁跟踪业务迁移后的真实归属，防止搬动文件或修改统计范围掩盖漏测。

## Non-goals

- 本次请求只创建待评审规格，不修改实现、不提前合并当前 specs、不宣称迁移已完成。
- 不实现 Linux/Windows UI，不改用其他 UI 框架，不为“薄桥”新增通用事件总线、插件框架或额外业务 crate。
- 不强制以推送取代轮询，不以行数或每个导出只能调用一次函数作为架构指标。
- 不改变现有持久化格式、会话隔离、权限保护和用户确认语义；现有代码与当前安全规格的偏差必须明确核对，不自动固化为新契约。
- 不把原生输入、动画、布局、屏幕坐标或文件选择器实现搬入核心。

## Capabilities

### New Capabilities

- `core-application`：定义业务完整性、领域状态唯一归属、应用服务、跨端复用、例外审查及迁移验收。

### Modified Capabilities

- `ffi-bridge`：明确薄桥边界、允许的机械适配、稳定导出与随业务迁移更新的覆盖率责任。
- `platform`：将“Rust 核心”明确为可独立消费的 `panda-core`，定义 UI 与平台服务边界。
- `workspace`：由核心持有共享逻辑状态、关闭决策和精确会话生命周期；消解遗留按主机推迟断开的规格冲突。
- `host-keys`：由核心统一协调首次信任请求、决策与等待者，UI 仅呈现并回传选择。
- `tab-groups`：分组逻辑允许由核心内存持有，继续不落盘、不跨应用重启保留。

## Impact

- Rust：涉及 `panda-core` 应用入口、现有配置/凭据/工作区/连接/任务模块，以及 `panda-ffi/src` 全部生产模块的职责审查。
- Apple：涉及 `PandaCoreBackend`、`PandaCoreBridge`、`AppModel`、凭据解析、连接门控、终端/SFTP/工作区/传输 Store 与 `AppBackend` 的真实实现和测试替身。macOS 与 iPadOS 同步切换到同一核心契约，保留各自原生 UI 和平台服务。
- 契约：现有 UniFFI 名称、参数、返回类型和同步外观原则上保持兼容；完整用例需要时可增加简单值类型接口。现有底层接口可作为兼容转发保留，但不得继续拥有业务规则或绕过安全校验。
- 构建与验证：涉及 FFI 生成链、双端构建/XCTest、Rust 核心与边界测试、`scripts/verify-rust-coverage.sh`、`scripts/ffi-contract-matrix.txt` 与模块边界检查。依赖仍须跨平台且许可证兼容。
- 提案衔接：`migrate-business-logic-to-rust` 的已实现算法与基础设施继续复用；其把业务保留在 FFI/Swift、推送替代轮询及替换文件选择控件等安排不作为本次验收依据。本提案获评审后，重叠的未完成任务按本提案边界协调，旧任务勾选不作为当前实现证据。

## 评审与验收范围

此次交付验收为 proposal/design/tasks/spec deltas 齐全、严格校验通过、需求与任务可追踪。实施验收另需核心直接调用与 FFI 契约对照、正常/意外/边界测试、Rust 覆盖率、macOS/iPadOS 构建及相关 XCTest；未执行的实现验证不得标记通过。
