## Context

见 proposal.md。顶部内容由 SwiftUI 绘制，AppKit 桥接负责透明标题栏、全尺寸内容与原生按钮。现有每次 attach 都无条件写属性；工作区已有 metrics 去重与分栏去重，本变更保留这些改动。焦点通知已由并行的工作区编辑补入，实施时以磁盘当前内容为准。

## Goals / Non-Goals

目标：以实际属性为依据实现幂等配置，用真实 NSWindow 和 Mock 内容测试焦点、重复更新、异常属性恢复。
不改业务层，不新增依赖，不通过周期刷新维持可见性。

## Decisions

- 先以 NSWindow 子类记录实际 setter 次数，建立重复更新与焦点通知的失败测试；用合成 SwiftUI 顶栏验证宿主，不启动真实后端。
- 根据当前窗口属性逐项判断后写入，优于只缓存策略：若系统重置透明度或 toolbar，策略缓存无法发现偏离。
- 完整 Mock WindowGroup 已验证：初始透明度为 true，打开页签/选择主机后变成 false，而 content frame 不变。SwiftUI 场景默认标题栏样式覆盖了 AppKit 的临时配置。主 WindowGroup 显式声明 `.windowStyle(.hiddenTitleBar)`，由场景持久表达无标题文字的样式，AppKit 仅校正实际偏差。这是可见性修复的核心；仅幂等保护无法解决遮挡。
- 保留窗口尺寸与焦点事件的校正入口；测量不变不发布。原生按钮仅在偏离目标状态时恢复。
- 观察窗口切换与异步回调需限于当前宿主，避免旧窗口回调干扰新宿主。
- 若几何与实际可见性仍失败，依据探针结果调整宿主布局，并记录证据；不把 setter 去重通过等同于视觉根因已确认。

## Risks / Trade-offs

- [Mock NSWindow 与 SwiftUI WindowGroup 行为可能不同] → 分别记录自动化验证边界，不能以合成窗口通过宣称用户场景复现。
- [原生按钮父视图属于系统所有] → 避免无条件修改其显示状态，测试窗口按钮与自绘内容同时可见。
- [工作区存在其他未提交改动] → 修改前备份，只修改相关代码与本提案，不回滚他人改动。
