## Why

当前 SFTP 文件传输在目标路径已存在文件时会直接覆盖，存在误操作风险。用户需要在覆盖前获得明确提示，并能看到源文件与目标文件的大小、最后修改时间，以便做出正确决策。

## What Changes

- 在 `panda-core` 的 SFTP 传输逻辑中增加目标文件存在性检测。
- 当检测到目标文件已存在时，传输不立即执行，而是向调用方返回覆盖确认请求，并携带源文件与目标文件的大小、最后修改时间。
- 扩展 FFI 绑定，使 Swift 端能收到覆盖确认请求及文件元数据。
- 在 SwiftUI 中新增覆盖确认弹窗，展示两个文件的元数据，并提供「覆盖」「保留两者」「跳过」选项。
- 用户选择后，根据选择结果继续、取消或重命名传输。

## Capabilities

### New Capabilities

- 无

### Modified Capabilities

- `sftp-transfer`：增加覆盖确认流程，要求在目标文件已存在时暂停传输并返回文件元数据对比信息。
- `ffi-bridge`：新增或扩展传输结果类型，以传递覆盖确认请求及文件元数据。

## Impact

- `crates/panda-core`：SFTP 上传/下载入口需新增目标存在性检查与元数据读取路径。
- `crates/panda-ffi`：可能新增 uniffi Record/Enum 类型用于覆盖确认请求。
- `apple/PandaSSH`：SFTP 文件传输 UI 需接入确认流程并展示弹窗。
- 平台范围：同时影响 macOS 与 iPadOS 双端；纯 UI 展示，业务逻辑仍由 Rust 核心处理。

## Non-goals

- 不实现自动重命名策略（保留两者仅作为后续可扩展点，本期聚焦提示与覆盖/跳过）。
- 不修改 SSH 连接、主机配置、known_hosts 等其他模块的行为。
- 不引入第三方文件对比/合并工具。
