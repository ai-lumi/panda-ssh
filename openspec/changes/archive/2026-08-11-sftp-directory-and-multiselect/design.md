## Context

当前 `SftpTabView` 的本地与远程文件栏使用 `FilePaneNavigator` 展示目录条目，并通过 `SftpSessionStore` 维护单选状态（`selectedLocal`、`selectedRemote`）和远程多选状态（`selectedRemoteItems`）。

- 本地栏：通过 `NSOpenPanel` / `UIDocumentPicker` 选择文件，仅支持文件多选；用户无法在文件栏内直接多选或选中目录。
- 远程栏：已存在多选模式，但仅限于文件项；目录项只能单击进入，不能作为批量下载源被选中。
- `sftp-batch-transfer` 已在 Rust 与 FFI 层实现单文件传输与批量扫描执行接口。

本次变更除让 UI 支持目录/多选外，还需将「选中目录」组织为**任务组**：每个顶层目录对应一个任务组，组内每个文件是独立 `TransferTask`；子目录不再生成子任务组；多选纯文件时不生成任务组。

## Goals / Non-Goals

**Goals:**
- 本地文件栏支持在栏内多选文件与目录项，目录项作为任务组、文件项作为独立任务。
- 远程文件栏的多选模式允许选中目录项，目录项作为任务组、文件项作为独立任务。
- 保持单击/双击目录进入目录的现有交互。
- 单选文件仍走单文件传输流程，保留覆盖确认行为。
- 任务组支持整体停止/继续/重试，组内每个文件任务支持单独控制。

**Non-Goals:**
- 不改变 Rust 单文件传输核心执行逻辑；Rust 批量扫描接口仅用于 Swift 侧预扫描目录内容。
- 不引入拖拽、剪贴板、右键菜单等新的交互方式。
- 不修改文件选择器（`NSOpenPanel` / `UIDocumentPicker`）本身的能力范围；仅调整栏内选择行为。

## Decisions

### 1. 任务组是 Swift `TransferStore` 层的组织概念

**决策**：任务组不对应 Rust 的单个批量任务，而是 Swift 侧根据目录边界将多个单文件 `TransferTask` 归为一组。Rust 仍按单个文件任务执行。

**理由**：
- 用户要求组内文件可单独停止/继续/重试，Rust 当前批量任务接口把所有文件封装在一个任务内，无法满足独立控制。
- Swift 已具备 `TransferTask` / `TransferStore` 模型，扩展分组字段比改造 Rust 批量执行器更轻量。

**替代方案**：扩展 Rust 批量接口，使其内部维护子任务并支持独立控制。该方案改动范围大、测试周期长，且 Swift 侧已有成熟任务模型。

### 2. 目录内容预扫描使用 Rust 批量扫描接口

**决策**：Swift 在创建任务组前，调用 Rust 的批量扫描接口（`scan_local_sources` / `scan_remote_sources`）获取目录下所有文件列表，再为每个文件创建单文件传输任务并标记为同一组。

**理由**：
- 复用 Rust 已有的递归遍历、符号链接循环检测、总大小计算能力。
- Swift 侧无需自己实现递归 SFTP 列举或本地目录遍历。

### 3. 本地栏统一使用栏内多选模型

**决策**：本地栏不再依赖系统文件选择器作为唯一多选入口，而是在文件栏内支持多选文件与目录。

**理由**：
- 与远程栏体验一致。
- 目录项可以直接作为任务组源被选中。

### 4. 远程多选模型扩展为 `Set<String>`，不限文件

**决策**：`selectedRemoteItems` 从仅收集文件名扩展为收集任意选中条目名称（文件或目录）。

**理由**：
- 目录与文件在任务组织层面都是条目名称，批量扫描时再区分类型。

### 5. 区分「进入目录」与「选中目录」的手势

**决策**：
- macOS：单击目录名进入目录；多选模式下勾选复选框即可选中目录作为传输源。
- iPadOS：点击目录行右侧的披露按钮或箭头进入目录；多选模式下勾选复选框选中目录。

**理由**：
- 避免在普通模式下误将「进入」变成「选中」。
- 复选框是多选状态的标准控件。

### 6. 多选纯文件时不生成任务组

**决策**：当多选集合中只包含文件（不含目录）时，为每个文件创建独立 `TransferTask`，不设置 `groupID`。

**理由**：
- 符合用户要求：只有目录才需要任务组聚合展示。
- 多个独立文件的进度、状态各自展示，便于用户区分。

## Data Model Changes

- `TransferTask` 新增 `groupID: UUID?` 与 `groupName: String?`。
- `TransferRecord` 同步新增分组字段。
- `TransferStore` 维护 `groups` 或按 `groupID` 聚合展示。
- 真实 FFI 源返回的记录 `groupID` 为 `nil`；任务组仅在 Swift 注入字段后展示。

## UI Changes

- `TransferPanelView`：任务组可展开/折叠，展示组名、总进度、总速度；展开后列出组内文件任务。
- 任务组行提供「停止全部」「重试全部」按钮；文件任务行保持单独控制按钮。
- `SftpTabView`：本地/远程栏进入多选模式后每行显示复选框，目录行同时保留进入按钮/指示器。

## Risks / Trade-offs

- **[Risk] 任务组内文件数量可能很大，创建大量单文件任务会增加内存与管理开销。**
  → Mitigation：任务组展示支持折叠，默认折叠大组；并发槽位仍由 Rust/FFI 全局控制，不受任务数量影响。

- **[Risk] 目录扫描需要一次额外 FFI 调用，大目录可能耗时。**
  → Mitigation：扫描异步执行，扫描期间任务组显示「扫描中」；后续可考虑后台预扫描优化。

- **[Risk] 单文件覆盖确认与任务组冲突处理的交互复杂。**
  → Mitigation：任务组内每个文件仍走单文件传输的覆盖确认流程；冲突弹窗展示文件路径与元数据。

## Migration Plan

无迁移成本。本 change 为 UI 行为与展示层扩展，不影响已有配置、主机数据或传输历史。
