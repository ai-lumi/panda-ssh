## Context

见 proposal.md。当前 shell 读接口以空字节数组同时表示“暂时无输出”和“读取器已因远端关闭而结束”；Swift 轮询器只有遇到异常才进入断开流程。连接缓存按主机与凭据保存 `SshSession`，只能在工作区确认该主机没有活动消费者时移除。

## Goals / Non-Goals

**Goals:**

- 保留远端关闭前已缓冲的全部终端输出，再报告 shell 结束。
- 将远端退出可靠地映射为共享 macOS/iPadOS UI 的断开状态。
- 仅在最后一个活动消费者结束且无传输时释放主机连接。

**Non-Goals:**

- 不以空输出、超时或后台探测推断断开。
- 不改变连接池的按凭据复用键或 SFTP 生命周期。

## Decisions

1. Rust shell 读取器单独记录远端关闭；`read` 先排空缓冲区，随后才返回会话已关闭错误。这样空闲终端仍返回空输出，而 `exit` 不会吞掉最后一屏信息。
2. 保持既有 FFI 函数签名，以已有错误通道传播“已关闭”，避免生成绑定和 ABI 变更。Swift 收到该错误后关闭本地 shell 句柄并转为失败/断开阶段。
3. 工作区根据同主机标签的已上报状态与传输队列决定是否调用既有 `disconnectHost`。仅状态为 `connecting` 或 `connected` 的标签阻止释放；失败态标签不再持有可用会话。

替代方案：为 `shell_read` 新增显式状态枚举。它更直观，但会扩大 UniFFI 契约和生成绑定变更范围；现有错误路径已能表达终态，故不采用。

## Risks / Trade-offs

- [读循环与关闭竞争] → 关闭标记与输出缓冲受同步原语保护；测试覆盖“先输出、后关闭”的顺序。
- [误断其他同主机会话] → 释放前检查全部标签的连接中/已连接状态与活跃传输。
- [断开后重复释放] → 连接池移除和 shell 关闭维持幂等语义，工作区只按当前状态触发。

## Migration Plan

不涉及持久化或协议迁移。部署后，已有打开的标签将在下一次远端 shell 关闭时采用新状态转换；出现回归时可回退本变更，不影响保存的配置或凭据。
