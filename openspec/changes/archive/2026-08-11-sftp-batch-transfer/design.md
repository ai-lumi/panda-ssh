## Context

当前 `panda-core` 的 SFTP 模块已实现单文件上传/下载、目录列举、远程文件管理及覆盖确认请求。SwiftUI 侧通过 `AppBackend` 协议与 FFI 调用核心能力，传输面板使用 `TransferStore` 管理任务状态与进度。现有进度回调按单个文件报告已传字节/总字节。

本变更将单文件能力扩展为批量能力：支持一次选择多个文件和/或多个目录，统一作为一个任务展示与执行。

## Goals / Non-Goals

**Goals:**
- 在 Rust 核心层实现批量上传/下载的递归遍历与执行，支持文件与目录混合选择。
- 保持单文件覆盖确认协议不变，批量传输中的冲突复用同一机制。
- 在 SwiftUI 侧将批量传输展示为单个任务，聚合显示总进度与速度。
- 支持用户取消批量传输，并隔离单个项目错误。

**Non-Goals:**
- 不实现增量同步、双向同步或差异比对。
- 不引入压缩/打包传输。
- 不实现远程目录间的复制/移动。
- 不处理复杂符号链接场景（循环除外）。

## Decisions

### 1. 批量遍历放在 Rust 核心层

**决策：** `panda-core` 负责递归遍历所有选中的本地/远程项目（文件或目录），并逐个文件调度 SFTP 操作。

**理由：** 业务逻辑必须全部落在 Rust 核心层（项目架构评审检查清单第 1 条）。Swift 侧只负责发起批量传输请求与展示聚合进度。

**替代方案：** 在 Swift 侧遍历目录后调用单文件接口。rejected：会破坏平台无关性，且 iPadOS 文件系统访问受限，核心层更适合做跨平台抽象。

### 2. 批量传输作为一个整体任务

**决策：** 从 Swift 侧看，一次批量上传/下载只产生一个 `TransferTask`，核心层内部将其展开为多个文件操作。

**理由：** 减少 UI 复杂度，保持传输面板简洁；聚合进度便于用户感知整体状态。

**替代方案：** 每个项目创建一个独立任务。rejected：选择数量可能很多，会导致面板拥堵，且难以展示批量整体进度。

### 3. 先遍历后传输（预扫描）

**决策：** 批量传输开始前先递归扫描所有选中的源项目，计算文件总数与总字节数，然后再开始实际传输。

**理由：** 能立即给出准确的聚合进度百分比和剩余时间；便于提前检测循环符号链接。

**替代方案：** 边遍历边传输。rejected：进度条会在传输前期不断跳动，用户体验差。

**权衡：** 预扫描会增加一点启动延迟；对于极深目录需要设置递归深度上限或超时。

### 4. 覆盖确认按项目触发

**决策：** 批量传输中每个已存在目标文件都会独立触发覆盖确认请求，暂停当前文件并等待用户决策。

**理由：** 复用现有 `sftp-transfer` 的覆盖确认协议，避免引入新的确认模型；给用户逐文件控制权。

**替代方案：** 提供「全部覆盖/全部跳过」批量选项。rejected：可作为未来增强，本变更先保持最小实现。

### 5. 错误默认继续，可选「遇错即停」

**决策：** 默认行为是单个项目失败后记录错误并继续；通过参数支持 `stop_on_error` 模式。

**理由：** 批量传输场景下用户更关注最终结果摘要；遇错即停留给需要严格一致性的用户。

### 6. 本地符号链接循环检测使用 inode + 设备号

**决策：** 本地目录遍历使用 `std::fs` 的元数据记录已访问的 `(dev, ino)` 对；远程目录遍历使用路径集合检测循环。

**理由：** 本地 inode 检测准确可靠；远程 SFTP 协议不暴露 inode，只能使用路径近似检测。

### 7. 多选源路径的根目录解析

**决策：** 批量上传时，每个本地源路径按其在文件选择器中的原始路径处理：文件直接上传到目标目录，目录则按相对目录结构递归上传。目标目录是所有项目的共同父目录，由 Swift 侧在发起请求时指定。

**理由：** 保持语义简单，避免用户困惑；与常见文件管理器拖拽行为一致。

**替代方案：** 自动计算源路径的最近公共父目录作为相对根。rejected：会增加实现复杂度，且用户不一定能预期相对路径结果。

### 8. 远程面板多选模式

**决策：** 远程文件列表支持进入多选选择模式，用户可多选文件/目录后点击「下载到本地」。

**理由：** 与本地文件选择器多选形成对称体验；选择模式避免日常浏览时误触批量操作。

**替代方案：** 始终显示复选框。rejected：会污染正常浏览界面。

## Risks / Trade-offs

- **[Risk]** 极深目录或大量小文件导致预扫描耗时较长，UI 长时间无进度。  
  → **Mitigation** 在扫描阶段也上报进度（如「扫描中…」文案），并限制递归深度；未来可加入异步增量扫描优化。

- **[Risk]** 远程文件列表在扫描后发生变化（新增/删除/修改），导致聚合总字节数与实际不符。  
  → **Mitigation** 在传输阶段动态修正总字节数，并在 UI 中说明总数可能变化。

- **[Risk]** 单个文件覆盖确认弹窗在批量传输中频繁出现，影响体验。  
  → **Mitigation** 后续可扩展「全部覆盖/全部跳过」批量确认；本次保持逐文件确认以保证正确性。

- **[Risk]** 批量传输取消后留下部分已传输文件，用户可能误以为完成。  
  → **Mitigation** 任务状态标记为 `cancelled`，并在面板中显示「已取消（已完成 N/M）」。

- **[Risk]** 多选文件数量不可控，一次性发起过大任务可能阻塞或内存占用过高。  
  → **Mitigation** 在预扫描阶段限制最大项目数与最大总字节数，超限时报错并建议分批处理。

- **[Risk]** macOS 与 iPadOS 本地文件选择器的多选行为存在差异（`NSOpenPanel.allowsMultipleSelection` vs `UIDocumentPicker`）。  
  → **Mitigation** Swift 侧通过抽象统一入口，将选中路径列表传给 Rust 核心，核心逻辑与平台无关。
