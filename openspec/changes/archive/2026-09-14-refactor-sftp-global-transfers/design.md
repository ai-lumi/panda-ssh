# 设计

## 现状与边界

SftpTabView.browserColumns 在文件面板前插入 toolbar；browserSurface 使用 macOS 遮罩侧滑面板及 iPadOS inspector/sheet。TransferStore 已保存 source、destination、hostID，并由工作区共享。连接监控已有 macOS 独立窗口、iPadOS 工作区页面模式。

## 方案

1. 删除额外 SFTP 工具栏，保留地址栏中的本地／远程标识、返回根目录、返回上级、路径编辑、刷新与选择操作。窄屏本地／远程切换继续可用。
2. 在全局导航的连接监控附近提供「传输任务」入口及活动任务数。macOS 打开或激活一个传输窗口，iPadOS 路由到全局任务页面。共享同一 TransferStore；打开页面不新建任务或连接。
3. 将现有任务列表改为自适应页面，移除 340 点固定宽度与 sidebar 样式。宽屏按列展示，窄屏每条任务分行显示全部字段。源／目标分别标明本地设备与远程主机，分别展示完整路径；长路径可截断显示，但必须可查看完整值。主机无法解析时使用 hostID，不编造名称。
4. 复用现有任务分组、暂停、继续、取消、重试和清理操作；入队仅提示，不弹面板或抢占页面。关闭页面不影响传输。
5. 光标原因尚未验证。实现前检查文本编辑器、终端和原生视图的 cursor rect／tracking 作用范围。按钮及非文本区域使用系统箭头，只有可编辑文本区域使用 I 形；避免在整个 SFTP 容器强制箭头而破坏输入。

## 左下角入口调整

主窗口左下角移除预留的「代码片段」按钮，在连接监控附近放置「传输任务」入口及活动任务数。代码片段功能暂不纳入开发范围，本次不清理已有片段数据。SFTP 右上角的原传输按钮随额外标题栏移除。

## 替代方案

保留可收起侧面板不能满足独立页面要求；为每个 SFTP 创建独立任务列表会重复已有全局数据。采用现有监控呈现模式，减少新增路由机制。

## 验证

先为新增路由和任务展示映射写失败测试，再最小实现。覆盖重复打开、无任务、多主机、上传／下载方向、未知主机、长路径、零字节、暂停、失败与取消。纯布局以构建和人工验收验证；光标需实际 macOS 指针交互验收，静态测试不能声称已验证。测试使用 fake，不访问真实 SSH 或钥匙串。

## 风险

工作区存在未提交的顶部栏改动，须基于当前代码增量整合。移除旧面板呈现状态前检查布局策略和测试的全部引用。若发现必须调整业务数据契约，先补充提案再实施。
