## Context

现有 Swift 层分别负责钥匙串读写与连接前解析，主机 TOML 仅保存引用。本变更按 proposal.md 与 `credential-protection` 规格把存储下沉到 Rust 核心，使 macOS/iPadOS 共享一致的格式和规则。

## Goals / Non-Goals

**Goals:**

- 在配置目录建立原子写入的凭据仓库，按主机 ID 与认证类型存取。
- 以无保护明文格式兼容既有数据；启用保护密钥后阻止未认证的读取与修改。
- 让 Swift 只负责收集瞬态输入和呈现状态，不实现加密或本地凭据规则。

**Non-Goals:**

- 不提供忘记保护密钥后的恢复；无法解锁时不得尝试弱化保护。
- 不将凭据纳入现有配置导出归档，也不支持跨设备同步。

## Decisions

### 独立凭据文件而非扩展 hosts.toml

在根目录新增单独凭据文件，主机记录继续只含稳定引用。这样导出主机配置不会意外携带密码，并能对整个凭据负载原子加密。备选方案是将密文嵌入 `hosts.toml`；它会扩大常规配置文件的敏感面并使导出边界不清晰，因此拒绝。

### 版本化信封与 AEAD

受保护文件使用包含格式版本、随机盐、随机 nonce 与密文的版本化信封。实现采用 Argon2id 默认参数派生 256 位密钥，并以 AES-256-GCM 加密和认证整个凭据负载；随机值由操作系统 CSPRNG 生成。格式版本锁定 KDF 参数，后续参数变更将提升版本。明文模式也带显式格式版本。备选的固定哈希或应用内硬编码密钥不能抵抗复制配置目录后的离线攻击，因此拒绝。

### 保护密钥仅驻留内存

设置页在设置/变更/移除时收集保护密钥；核心用它执行一次校验和重写，不持久化。启动后尚未解锁时，读取受保护凭据返回结构化“需要保护密钥”错误，UI 请求用户输入。备选的把派生密钥写回配置目录会失去密码保护意义，因此拒绝。

### 迁移必须先验证、再原子替换

变更和移除保护密钥时，先完整读出并验证旧格式，再在同目录临时文件写入新信封并 rename。任何步骤失败均保留原文件。创建新的保护密钥时不得覆盖无法解析的旧文件。

## Risks / Trade-offs

- [未设置保护密钥即明文] → 设置页持续展示明显警告；该模式为用户指定的兼容行为，不作安全承诺。
- [忘记保护密钥会失去访问] → 在确认设置与变更前提示不可恢复，并通过测试验证错误路径不损坏文件。
- [新增加密依赖与移动端构建风险] → 只选择 Rust 生态中 Apache-2.0/MIT/BSD 兼容且跨平台的库，加入前核验许可证并在三 Apple target 编译。
- [写入失败导致主机/凭据不一致] → 先更新凭据、后保存主机；凭据删除与主机删除的失败处理需要可重试且不制造悬空引用。

## Migration Plan

1. 先以 Rust 单元测试定义明文读写、加密读写、错误密钥、篡改、原子重写和删除语义。
2. 增加 FFI 的凭据与保护密钥操作，保留主机 TOML 引用格式。
3. 替换 Swift 钥匙串服务与解析调用，接入设置页和错误提示。
4. 更新导入导出提示，并验证旧明文凭据在未设置保护密钥时仍可读取。
5. 回滚时保留凭据文件格式兼容读取；已加密文件不能安全降级为旧版本，需通过应用内移除保护密钥后再回滚。
