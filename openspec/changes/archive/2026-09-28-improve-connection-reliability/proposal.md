# 连接可靠性：会话持久化 + 自动重连 + 端口转发

> 状态：草案 | 创建日期：2026-09-09 | 关联路线图：brainstorming-ai-era-roadmap.md 1.4、8.5（Phase 0）、#2

## 问题

路线图 1.4 识别三项连接可靠性缺口，阻碍日常运维与后续高级场景：

1. **恢复与重连**：当前终端标签断线后仅保留手动重试入口（`connection-pool/spec.md`「连接失效检测与重连」），无自动重连、无会话状态持久化、无远端进程恢复承诺。用户切出 App（iPadOS 多任务切换、macOS 合盖睡眠）或网络瞬断后，必须手动关闭并重新打开标签页，丢失全部终端上下文。
2. **端口转发**：路线图 1.4、场景 15/16/17 均要求本地转发、反向转发和动态转发（SOCKS），当前无任何规格或实现。开发者高频依赖此能力访问内网服务。
3. **连接所有权与复用边界**：`connection-pool/spec.md` 现行设计为所有者独占（第 9-80 行），残留复用条款（第 82-100 行）待清理（已由 `resolve-baseline-conflicts` 提案处理）。本提案在此基础上扩展自动重连与端口转发，不恢复全局池。

这些缺口导致：
- 网络不稳定环境下用户体验断裂，终端标签无法自动恢复
- 开发者无法通过 Panda SSH 建立 SSH 隧道，被迫切换到命令行或其他工具
- 后续跳板机、批量执行等高级场景缺乏可靠的连接基础

## 目标

1. **会话持久化**：终端标签的会话元数据（主机、凭据引用、PTY 尺寸、终端状态）在 App 生命周期内持久化，支持 App 重启后恢复标签页结构。
2. **自动重连**：终端标签检测到连接失效后，按可配置策略自动尝试重连，用户可感知重连进度并手动干预。
3. **远端进程恢复**：明确区分三层恢复承诺——工作区 UI 恢复、SSH 传输重连、远端进程（shell 会话）恢复。远端进程恢复依赖 tmux/screen 等远端多路复用器，本提案不承诺无辅助的远端进程恢复。
4. **端口转发/隧道管理**：支持本地转发（`-L`）、反向转发（`-R`）和动态转发（`-D`，SOCKS5），按所有者独占连接，明确监听范围、生命周期和端口冲突处理。

## 范围

### 包含

- 终端标签会话元数据持久化（主机 ID、凭据引用、PTY 尺寸、标签位置）
- 自动重连策略（指数退避、最大重试次数、用户可配置）
- 三层恢复语义定义与分别验收
- 本地端口转发（Local Forwarding）
- 反向端口转发（Remote Forwarding）
- 动态端口转发（Dynamic Forwarding / SOCKS5）
- 端口转发生命周期管理（随所有者、随标签页、独立长生命周期）
- 端口冲突检测与处理策略
- macOS 与 iPadOS 平台差异约束

### 不包含

- 远端进程无辅助恢复（不内置 tmux/screen 自动安装或会话注入）
- 连接池全局复用（保持所有者独占设计）
- X11 转发（低优先级，后续按需提案）
- 跨 App 重启的 TCP 连接保持（操作系统限制，不在客户端能力范围）
- 跳板机链上的端口转发（跳板机提案独立处理）

## 验收标准

- [ ] 终端标签在 App 进入后台后返回，连接存活或自动重连成功，用户无需手动关闭重开
- [ ] 自动重连在指数退避达到最大重试次数后停止，显示明确失败状态和手动重试入口
- [ ] 自动重连期间终端标签显示重连进度（当前重试次数、等待时间）
- [ ] 本地端口转发可建立并监听指定本地地址:端口，转发到远端指定地址:端口
- [ ] 反向端口转发可在远端监听指定地址:端口，转发到本地指定地址:端口
- [ ] 动态端口转发可在本地建立 SOCKS5 代理，通过 SSH 连接转发流量
- [ ] 端口冲突（本地端口被占用）时返回明确错误，不静默失败
- [ ] 端口转发的连接按所有者独占，不跨标签页或跨任务共享
- [ ] iPadOS 端口转发受平台限制时（无后台监听），明确提示不支持或受限
- [ ] 所有新能力有 Rust 核心单元测试，覆盖率满足 95% 门禁
- [ ] 所有 spec 变更经评审后合并回 `openspec/specs/`

## 风险

- **中风险**：自动重连需处理凭据过期（密码变更、密钥轮换）、主机密钥变更等安全场景，不能盲目重试
- **中风险**：iPadOS 后台限制可能影响端口转发的实际可用性，需明确平台边界
- **低风险**：端口转发为成熟 SSH 协议特性，russh 已支持 `channel_open_direct_tcpip` 和相关请求
- **依赖**：`resolve-baseline-conflicts` 提案先完成连接池残留条款清理

## 后续工作

- 跳板机提案可基于稳定的重连机制设计跨跳恢复

- 端口转发为内网访问场景（场景 7/15/16/17）提供基础能力
