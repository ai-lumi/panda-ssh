## Context

见 `proposal.md`。SFTP 会话层在上传开始时捕获当前远端目录，并将本地路径交给批量扫描器。批量扫描器的契约是将每个源路径的顶层名称追加到传入的目标目录后，再递归生成子项路径。当前目录上传调用已预先追加顶层名称，造成重复。

## Goals / Non-Goals

**Goals:**

- 将目录上传的路径拼接职责收敛到批量扫描器。
- 覆盖包含中文名称的顶层目录与文件，验证目标路径只保留一层顶层目录名。
- 保持上传发起时捕获目标目录的并发语义。

**Non-Goals:**

- 不修改 Rust 扫描器、FFI 契约或远端目录创建逻辑。
- 不改变单文件上传、多选文件上传、下载或冲突处理。

## Decisions

### 仅把当前远端目录传入目录扫描器

目录上传循环将已捕获的当前远端目录直接传入扫描器，不再在 Swift 侧追加本地目录名。扫描器是所有批量源路径生成相对目标结构的唯一边界，因此能同时保持单目录和多目录场景一致。

替代方案是在 Rust 层抑制目录名追加，但会破坏直接调用批量扫描器的既有契约；在传输任务层剥离重复目录名则缺少源路径与目标目录的语义，且会掩盖调用边界错误。

### 用会话层回归测试模拟扫描器契约

XCTest 注入的本地扫描处理器将按真实扫描器规则追加源路径 basename。测试通过目录上传后的传输任务目标路径断言修复前会失败、修复后只出现一层顶层目录名，并保持中文字符不变。

## Risks / Trade-offs

- [测试注入实现与 Rust 扫描器偏离] → 测试处理器仅实现与本缺陷相关的 basename 追加规则，断言最终任务目标路径；Rust 现有递归上传集成测试继续覆盖扫描器本身。
- [空目录不产生文件传输任务] → 本修复不改变既有空目录执行路径，避免将无关行为混入目录名重复修复。

## Migration Plan

- 不涉及数据迁移、配置变更或发布兼容性调整。
- 在 macOS 与 iPadOS 共享会话层构建中执行相关 XCTest。
- 如需回滚，仅回退该 Swift 调用参数及对应测试；不会影响已上传文件。
