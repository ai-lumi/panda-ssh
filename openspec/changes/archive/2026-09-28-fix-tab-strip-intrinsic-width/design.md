## Context

见 proposal.md - Why。本次只调整 SwiftUI 呈现层的尺寸与滚动装配，不下沉或新增页签业务规则。现有代码及未提交改动提供以下证据，但尚未完成运行时复现：

- `UnifiedWorkspaceTabStrip.swift:63–73` 的非滚动布局把可压缩的 `tabDocument` 与固定 `trailingEmptyWidth` 并排；后者由上一轮 `tabFrames` 得出，存在历史空白反向限制新内容的路径。
- `UnifiedWorkspaceTabStrip.swift:39、87–90、406–420` 用布局后的单页签帧推导文档宽度，并且只在滚动分支报告可视宽度。已分配尺寸不一定等于自然内容尺寸，尚未测量也不等于实际零宽。
- `TabStripViewportState.swift:55–62` 以最后一个按钮的右缘加留白推算文档宽度；完整内容测量应独立覆盖分组装饰。
- `TabStripViewportStateTests.swift:42–50` 只验证人工宽度的差值，不能揭示真实文字压缩后的测量反馈。
- 外层分配不依赖页签数；现有变更 `fix-macos-tab-drag-and-titlebar-zoom` 已约束空白命中区和排序事务。本提案不撤回这些约束。

不能仅凭 `ScrollView.frame(maxWidth:)` 推断滚动内容被压缩；实施前通过宿主布局测试记录内容宽度、按钮帧、可视宽度、尾部空白和溢出状态，验证具体因果链。

## Goals / Non-Goals

**Goals:**

- 形成“自然内容 → 实测文档尺寸 → 可视区与空白分配 → 滚动边界”的单向尺寸关系。
- 优先复用已有 SwiftUI `HStack`、`ScrollView`、几何测量及 XCTest 能力，不引入框架或新交互。
- 让实际布局回归与纯尺寸计算测试分别覆盖测量正确性和边界正确性。

**Non-Goals:**

- 不测量字符数、手工累加字形宽度，也不复制一套仅测试用的页签宽度算法。
- 不重写滚轮输入归一化、连接生命周期或排序事务。
- 不使用高于 macOS 14 / iPadOS 17 的专有滚动 API，不引入持久化尺寸缓存。

## Decisions

### 1. 由完整页签文档自然展开，而不是估算文字

优先在实际页签内容文档的合适边界使用 `.fixedSize(horizontal: true, vertical: false)`，让标题、关闭按钮和分组标签共同按理想横向尺寸布局；保留现有高度、样式和交互。其含义是随内容变化的理想宽度，不是给定一个固定数值。测量对象必须包含文档两端 padding，不只测 `Text`。

官方依据：[Apple fixedSize(horizontal:vertical:)](https://developer.apple.com/documentation/swiftui/view/fixedsize(horizontal:vertical:)) 明确横向理想宽度可容纳完整字符串，也提示内容可能超出父边界。因此必须配合真正的滚动可视区，而不能只去掉截断就让内容越界覆盖控件。[Apple fixedSize()](https://developer.apple.com/documentation/swiftui/view/fixedsize()) 描述父子尺寸提议及理想尺寸的关系。

替代方案：字符数乘平均字宽不适用于比例字体、不同语言和附件；只给文字提高布局优先级会转而挤压其他组件；统一宽度或均分宽度均不符合已确认方向。

### 2. 保持一个滚动容器，让空白成为布局结果

优先保持同一结构位置的横向 `ScrollView`，内部文档持续采用自然宽度，无论内容是否溢出都不把文档移入另一棵布局树。页签栏仍由现有外层 chrome 分配有限宽度。

定义：`C` 为包括留白的自然文档实测宽度，`W` 为页签栏分配宽度，`V` 为扣除实际浏览控件占用后的可视宽度。

- 尚未得到有效 `C` 时，用 `W` 作为临时可视区，不把未测量当成真实零宽去预留整栏空白；文档仍以自然宽度布局。
- 无溢出时，可视区宽度取自然内容与可用空间的较小值，剩余区域用弹性空白占据；空白不再通过历史差值以固定宽度挤压内容。
- 有溢出时，显示既有左右浏览按钮，滚动可视区使用扣除控件后的剩余宽度；页签栏内不再保留虚假的尾部空白。
- 是否显示浏览控件依据 `C` 与完整 `W` 比较，而不是与已经扣掉按钮的 `V` 比较，避免临界点自我维持溢出。沿用当前 0.5pt 比较容差，`maximumOffset = max(0, C - V)`；极窄或零宽输入安全归一化，不派发无效滚动。
- 弹性空白上继续使用既有 `macOSWindowDragRegion()`，仅实际非零空白参与拖窗命中；外层独立安全拖窗区不变，不铺设覆盖整个页签栏的事件层。

官方依据：[Apple ScrollView](https://developer.apple.com/documentation/swiftui/scrollview) 区分底层内容与当前可见部分。社区参考：[GeometryReader - Blessing or Curse?](https://fatbobman.com/en/posts/geometryreader-blessing-or-curse/) 讨论几何回写布局时的反馈风险。以上支持采用标准布局组合，并不代替本项目的失败测试或运行证据。

替代方案：在现有双分支上仅补一个 `fixedSize` 可能解除压缩，但仍保留滚动容器重建、空白旧值和可视尺寸单边更新的复杂性；整栏一直铺满 ScrollView 则会吞掉原本应可拖窗的空白。

### 3. 分离文档尺寸与按钮定位，并协调测量时序

在真实文档上通过现有几何/Preference 机制报告完整自然尺寸；`tabFrames` 保留为活动页签及浏览目标定位信息。不得再把压缩后的按钮集合当作文档自然宽度的唯一来源，也不得将旧坐标中已删除的 UUID 继续用于滚动目标。

可视宽度在两种占用状态下均能更新。增删页签、标题/字体/分组变化以及窗口/侧栏尺寸变化后，重新取得当前布局信息；只有尺寸或布局目标确实变化才回写和调整边界，避免每次几何回调都无条件 `scrollTo`。真实空文档须归零边界和锚点；未测量与空文档明确区分。

活动页签显露在当前尺寸和目标帧就绪后执行：可完整容纳时最小位移显露，超宽时选择动作先显露前缘；随后用户手动浏览不得因重复几何回调而被拉回。布局变化时重新夹取旧偏移，不能仅因目标数值等于旧 `viewportOffset` 就认定实际滚动已经完成；以宿主测试核实浏览控件出现及可视区变化后的实际位置，不只检查模型值。

替代方案：延迟固定毫秒后滚动、强制刷新 `.id`、每次新增清空所有状态，都可能掩盖时序问题或破坏交互连续性，不采用。

### 4. 超宽页签保留完整内容，按区段访问

同一个页签可能天然宽于整个可视区。此时保留一行完整标题，不新增截断、字号缩放或最大宽度；选择时露出前缘，用户可继续向右浏览至关闭按钮。规范同时修订两处“最右侧页签完整显露”的相关条目，避免仍要求物理上不可能的一次全显露。

替代方案：为极长标题另设最大宽度会违背已确认的自然展开策略，也会引入新的标题展示规则。

### 5. 先验证真实布局，再实现与重构

- Red：在隔离后端、无真实 SSH 连接的 SwiftUI 宿主中复现新增/关闭/再新增。以相同实际视图在不受横向压缩时的测量作为基准，比对页签真实宽度，而不是写死字符宽度或测试复制出来的替身布局。记录每轮容器、内容、按钮与空白尺寸。
- Green：先消除自然尺寸反馈，再接入文档/视口边界与显露；每个实现任务必须有对应已失败的行为测试。
- Refactor：保持实际渲染与测试共用同一视图。若需要抽出可测布局组件或快照，放在对应 Red 之后，不提前重构生产实现。
- macOS 使用真实宿主及 AppKit 命中测试；iPadOS 使用共享 SwiftUI 视图的 UIKit 宿主验证。纯 `TabStripViewportState` 测试仍负责正常、无效输入和临界值。

## Risks / Trade-offs

- [Risk] 极长标题会增加文档宽度 → 不删减内容，测试连续浏览、最后关闭按钮和超宽活动页签前缘；不要求整页签同时显示。
- [Risk] padding 重复计入或文档坐标与可视坐标混用 → 文档尺寸包含 padding 一次，按钮定位明确同一文档坐标系，并验证末端无空白超滚。
- [Risk] 首次测量、浏览按钮出现与几何回调不同步 → 区分未测量/空文档，对当前尺寸就绪后的显露做宿主级断言；禁用无位移的重复滚动。
- [Risk] 弹性空白被滚动宿主吞掉或事件视图越界 → 滚动容器只占应占区域，验证真实宿主命中点与页签、关闭和浏览按钮不重叠。
- [Risk] 字体或语言导致快照尺寸不稳定 → 与同环境自然布局基准比较并使用有界几何容差，不写死跨平台字形像素。
- [Risk] 多个未完成变更同时修改相关文件 → 开始实现前再次检查工作区差异，只叠加本提案必要更改；记录已有测试失败，不覆盖、回滚或冒领其他变更。

## Migration Plan

1. 评审本提案，确认自然宽度、显式空白和超宽页签约束。
2. 在当前工作区记录相关测试基线与真实布局失败证据，再依 tasks.md 分阶段执行 Red → Green → Refactor。
3. 运行受影响的双端 XCTest、Rust 测试及覆盖率门禁，再进行不连接真实主机的双端受控验收；macOS 重点复核空白拖窗、双击缩放和页签拖放。
4. 无数据或 FFI 迁移。回退仅撤销本提案新增的 UI/测试更改，不恢复整文件或丢弃其他未提交改动。
5. 全部验收完成后再同步并归档规范；不得仅凭规划文件齐全认定实现完成。
