## Why

用户报告新增页签后标题被压缩截断，关闭一个页签后恢复，再新增又复发。当前非滚动布局使用上一轮测量结果固定右侧空白，可能形成“空白限制页签宽度 → 测得压缩宽度 → 继续保留空白”的反馈；需要以自然布局和实测尺寸建立可回归验证的宽度契约，而不是按字符数估宽或仅修饰文字。

## What Changes

- 页签由 SwiftUI 按完整标题、状态图标、类型图标、关闭按钮和内边距自然撑开，不采用字符数估算、统一固定宽度或均分栏宽；新增、关闭和标题变化不得把其他页签锁在旧宽度内。
- 以整个页签文档的未压缩实测宽度判断溢出，覆盖分组标签、分隔线、按钮间距和两端留白；单个页签帧继续用于定位，不作为完整文档尺寸的唯一来源。
- 容器宽度只决定可视区与滚动范围。内容放得下时，剩余空间仍作为显式空白拖窗区；空白区不得反向限制自然宽度测量。
- 浏览控件出现、窗口缩放和侧栏变化后，依据真实可视宽度重新计算边界；保留稳定滚动容器，避免旧偏移与新容器位置脱节。
- 明确极长页签边界：自然宽度大于可视区时不缩字或省略标题，通过横向滚动分别访问完整标题各部分及关闭按钮，不要求物理上同时显示整个页签。
- 补充真实 SwiftUI 布局回归，覆盖“新增 → 关闭 → 再新增”、首次测量、分组、动态标题、溢出临界点和超宽单页签；继续保留既有拖窗、选择、关闭和排序语义。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `unified-workspace-chrome`：增加页签自然展开、完整内容实测和空白区单向布局要求，细化滚动边界及超宽页签的可访问性约束。

## Impact

- Swift UI：主要涉及 `apple/PandaSSH/Workspace/UnifiedWorkspaceTabStrip.swift`、`TabStripViewportState.swift`，必要时调整 `UnifiedWorkspaceChrome.swift` 中空白区布局装配。
- 测试：扩展 `apple/PandaSSHTests/TabStripViewportStateTests.swift`，新增覆盖实际宿主布局的测试；复用窗口事件与页签拖放回归测试。
- macOS：修复页签压缩，继续只允许显式空白区域拖窗及双击缩放，不以覆盖页签的透明事件层解决布局问题。
- iPadOS：使用相同自然宽度与滚动规则，不引入 AppKit 依赖或平台业务分支；验证窄窗口和字体尺寸变化。
- Rust/FFI、凭据、SSH/SFTP 生命周期和持久化格式均不变；不新增第三方依赖，不提高部署版本。
- 与 `fix-macos-tab-drag-and-titlebar-zoom` 修改区域交叠，但保留其空白区事件和排序事务约束，不覆盖其未提交实现，也不代其勾选验收任务。

## Non-goals

- 不改变页签视觉风格、关闭确认、分组规则、连接或重连行为。
- 不新增最大标题长度、缩写、字号缩放、均分宽度或持久化宽度缓存。
- 不恢复旧版 AppKit 页签栏，不引入新的底层布局框架。
- 不在此提案中实现或宣称根因已由运行时复现；实现前必须先获取失败测试和布局数值证据。
