## Context

参见 `proposal.md` 的故障动机。当前 Rust 全局连接池按 `(host_id, credentials)` 缓存强引用，FFI 的终端、SFTP 和传输入口均可取得同一 `SshSession`；Swift 工作区又按主机协调最后标签关闭。并发握手不在同一临界区内，且终端重试同时由按钮路径与视图任务路径触发。SSH 配置把 inactivity timeout 与 keepalive 都设为 30 秒，使空闲连接存在定时器竞争。现有监控以 Transport 为中心，但没有稳定所有者语义；Swift 日志没有覆盖底层关闭错误。

约束包括：业务生命周期必须落在 `panda-core`；UniFFI 导出保持同步并复用全局 tokio runtime；macOS/iPadOS 业务语义一致；凭据和终端内容不得进入遥测或日志；按 TDD 修改并满足 Rust/Swift/覆盖率/双平台构建门禁。

## Goals / Non-Goals

**Goals:**

- 让连接生命周期只有一个明确所有者，关闭传播范围可由句柄静态推断。
- 保留 SFTP 标签内的长连接体验，同时隔离标签之间及后台任务。
- 让终端重试成为按代次单飞的状态转换，消除重复 Transport。
- 让健康状态来源于真实 I/O、keepalive 与 Channel 事件，并提供可追踪日志。

**Non-Goals:**

- 不实现跨标签复用、连接预热或 OpenSSH ControlMaster。
- 不把活动连接恢复到应用重启之后。
- 不改变认证、known_hosts、传输调度和文件冲突产品规则。

## Decisions

### 1. 以显式所有权注册表替代连接缓存

核心层移除按主机/凭据取复用连接的 API。每次终端、SFTP 标签或运行中的传输开始时直接建立新 `SshSession`。保留一个只存弱引用和所有者元数据的活动连接注册表，供遥测与按连接标识健康检查使用；注册表不能返回连接给业务操作，因此不会退化成缓存。

备选方案是修复原连接池的并发单飞并引用计数。它能消除同秒重复握手，却仍让 `exit`、主机级断开和错误传播跨越用户可见会话边界，不满足隔离目标。

### 2. 终端与 SFTP 使用稳定句柄，传输使用任务内 RAII

FFI 终端句柄拥有一个 shell Channel 及其专属 Transport；关闭句柄依次关闭 Channel 和 Transport。SFTP 打开接口返回稳定句柄，后续目录与文件操作都指定该句柄，并在标签关闭时精确释放。传输在任务执行体内建立连接并通过作用域守卫在所有终态释放，不暴露给工作区。

备选方案是让每次 SFTP 操作独立握手。实现更简单但会显著增加目录浏览延迟和服务器负载，因此只移除跨标签复用，不移除标签内部复用。

### 3. 终端重试只有视图任务一个建连执行器

重试按钮只推进 `attempt` 代次并重置显示状态，不直接调用建连；视图的代次任务是唯一执行器。Store 同时记录当前在途代次，拒绝同代次重复开始，并在旧代次回调到达时忽略陈旧结果。

备选方案是保留按钮直接建连并移除视图任务。它会让解锁、视图重建和重连取消更难统一，故不采用。

### 4. 关闭 inactivity timeout，保留 keepalive 判失效

SSH 客户端配置将已认证会话的 inactivity timeout 设为无，keepalive 维持固定间隔和有限失败次数。空闲仅表示近期没有应用流量；只有 EOF、I/O 错误、连续 keepalive 失败或操作错误才能变为异常。

备选方案是将 inactivity timeout 延长。任何固定无业务流量超时仍会把正常空闲误判为故障，不符合监控语义。

### 5. 遥测和日志携带非敏感所有者元数据

建连入口传入所有者类型与随机标签/任务标识。Transport 快照记录该元数据；生命周期事件通过既有 Swift 日志设施记录，底层错误向 FFI/Store 显式返回，不再使用静默 `try?`。记录原因枚举而不是原始 I/O 内容。

备选方案是只凭 Channel 列表推断归属。通道结束后归属会丢失，也无法可靠区分标签和后台任务。

## Risks / Trade-offs

- [同一主机并发 Socket 数增加] → 不再共享是刻意取舍；继续由传输并发上限约束后台连接，监控显示实际数量，后续若要优化必须引入用户可见且可关闭的显式策略。
- [SFTP 句柄迁移影响面大] → 先以 FFI fake server 测试锁定打开、操作、关闭和无效句柄，再迁移 Swift 调用点，最后删除旧无状态入口。
- [异步取消可能跳过正常关闭握手] → 使用 Drop/作用域守卫保证本地 Transport 释放，并把强制释放记录为显式取消；不得依赖远端确认才能清理。
- [弱注册表残留过期条目] → 每次快照和查找惰性清理无法升级的弱引用；释放测试验证不再报告健康。
- [旧回调污染新重试状态] → 所有终端回调携带 attempt 代次，Store 只接受当前代次。

## Migration Plan

1. 先增加失败测试：空闲超时配置、独立 Transport、句柄精确关闭、终端单飞重试、SFTP/传输隔离和生命周期日志。
2. 增加活动连接弱注册表与所有者元数据，关闭 inactivity timeout；保持旧池暂时可编译。
3. 将 shell、SFTP、单文件与批量传输迁移到显式连接；Swift 迁移到句柄调用并删除主机级关闭协调。
4. 删除连接缓存、`disconnect_host` 与旧无状态 SFTP 工作区路径，重新生成 UniFFI 绑定。
5. 运行全量测试、95% 覆盖率、Rust 多目标检查及 macOS/iPadOS 构建；人工用同主机双终端执行 `exit`、重试和空闲检查验证。
6. 若回滚，恢复 FFI 与 Swift 调用契约及连接池模块的同一提交；本变更不迁移持久化数据，因此无数据回滚步骤。
