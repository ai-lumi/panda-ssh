## Context

`CredentialResolver` 已能返回“需要手动输入”，FFI 也有 `MissingPassword`，但未知主机探测失败后的放行和终端/SFTP 发起连接路径仍可能以空凭据进入会话。会话失败后共用视图没有错误分类，固定渲染“连接超时”。

## Goals / Non-Goals

**Goals:**

- 用一个可测试的连接前/连接结果状态机表达“需要密码”“需要口令”“网络超时”“认证失败”等互斥状态。
- 所有终端与 SFTP 入口在缺凭据时回到当前标签页的输入流程。

**Non-Goals:**

- 不改变服务器认证协议、连接超时阈值或凭据持久化策略。
- 不在认证失败时无限循环弹出输入框；服务器拒绝凭据仍是认证失败。

## Decisions

### 以结构化错误驱动 UI 转换

保留 FFI 的 `MissingPassword`，并补充/映射私钥口令缺失的结构化错误；Swift 会话层把这些结果转换为门控的凭据输入状态，而不是 `.failed`。网络/认证/主机密钥错误保留各自类型。备选的通过 `localizedDescription` 匹配字符串不稳定且不可测试，因此拒绝。

### 连接启动前再次守卫凭据

门控检查仍为首道防线；终端与 SFTP 在真正调用 FFI 前再次验证解析结果。该冗余是为异步 TOFU、凭据文件状态变化和未来入口复用提供边界保护。若第二次检查失败，直接展示输入窗口，不发出空凭据连接。

### 密码和口令独立提示文案

输入 sheet 根据认证方式显示“密码”或“私钥口令”，并将输入作为仅当前 tab 的瞬态状态。空提交保持禁用；取消关闭 tab，符合现有门控语义。

## Risks / Trade-offs

- [错误分类遗漏] → 为终端、SFTP、门控和 FFI 映射分别写正常、错误与边界测试。
- [TOFU 探测网络失败后误导用户] → 只在本地凭据解析失败时提示输入；探测网络失败且凭据可用时仍交给真实连接展示网络错误。
- [重复的凭据检查] → 增加少量读取成本，换取不带凭据进入网络层的正确性。

## Migration Plan

无需数据迁移。先编写会话状态/错误映射失败测试，再接入终端与 SFTP；以现有假 SSH 服务验证 `MissingPassword`、真实 timeout、认证失败三条路径各自呈现。
