# 代码片段深化

> 状态：草案 | 创建日期：2026-09-09 | 关联路线图：brainstorming-ai-era-roadmap.md 5.2、5.7、#1、#10、#11、#13、#14

## 问题

路线图 5.2 识别代码片段为 Phase 0 已决基础方向，当前已实现基础 CRUD（`SnippetStore`、FFI 绑定、SwiftUI `SnippetsView`），但以下能力缺失，限制了片段作为命令复用核心载体的价值：

1. **标签为平级字符串**：当前 `tags: Vec<String>` 无层级结构，无法表达"网络/内核参数"等分类关系。路线图 5.7 已决采用多级路径标签（`/` 分隔 + `tags.toml` 索引），但尚未实现。
2. **无片段搜索**：列表只能全量浏览，无法按标题、标签或内容关键词检索。
3. **无终端选文入口**：用户在终端中选中文本后，无法一键创建片段，需手动复制粘贴。
4. **无参数化模板**：片段为静态文本，无法嵌入变量（如 `{{host}}`、`{{port}}`），每次使用需手动替换。
5. **无标签管理 UI**：用户无法浏览标签树、重命名标签或查看标签下片段。

这些缺失导致：
- 片段数量增长后难以定位和分类
- 复用效率低，无法快速从终端操作转化为可复用片段
- 无法作为后续批量执行和巡检 Skill 的参数化命令来源

## 目标

1. 实现多级路径标签系统，与现有 `tags: Vec<String>` 兼容。
2. 实现片段全文搜索（标题、标签、内容）。
3. 实现终端选文 → 片段入口。
4. 实现参数化模板引擎（变量替换 + shell 转义）。
5. 实现标签管理 UI（树形浏览、重命名、删除）。

## 范围

### 包含

- 多级路径标签：`/` 分隔符、`tags.toml` 索引、OR/AND 过滤
- 标签管理：创建、重命名、删除、树形浏览、自动补全
- 片段搜索：标题/标签/内容关键词，Rust 核心实现
- 终端选文 → 片段：SwiftTerm `selectedText` 入口
- 参数化模板：`{{变量名}}` 语法、变量列表、展开预览、shell 转义
- 现有 CRUD 保持不变，新功能在现有基础上增量

### 不包含

- 片段执行（批量执行提案独立设计）
- 片段版本管理（巡检提案设计引用冻结）
- 片段分享/导入导出（团队协作提案后续设计）
- 主机标签（与片段标签分开，主机多维选择需独立数据模型）

## 验收标准

- [ ] 多级标签：片段可挂多个层级标签（如 `网络/内核参数`），标签树形展示，子树查询正确（`tag == prefix` 或 `tag.starts_with(prefix + "/")`）
- [ ] 标签兼容：现有平级标签无迁移损失，含 `/` 的旧标签正确解释为层级路径
- [ ] 标签过滤：默认 OR（匹配任一标签即显示），可切换 AND（匹配全部标签）；空选择显示全部
- [ ] 标签管理：可创建/重命名/删除标签；重命名级联更新所有关联片段；删除标签不删除片段
- [ ] 片段搜索：按标题、标签、内容关键词搜索，结果实时过滤
- [ ] 终端选文：终端中选中文本后，可通过菜单/快捷键创建片段，选中文本预填到代码区
- [ ] 参数化模板：片段代码中可嵌入 `{{变量名}}`，使用时展示变量列表和展开预览
- [ ] shell 转义：模板变量展开时正确转义 shell 特殊字符，防止注入
- [ ] 业务逻辑在 Rust 核心（`panda-core`），Swift 侧仅通过 FFI/`AppBackend` 调用
- [ ] 所有新增代码满足 TDD：先写失败测试，再写最小实现，覆盖率 >= 95%

## 风险

- **中风险**：多级标签重命名需级联更新多个 Markdown 文件的 frontmatter，需保证原子性和失败恢复
- **中风险**：模板引擎的 shell 转义需覆盖多种 shell 上下文（单引号、双引号、裸参数），实现复杂度需控制
- **低风险**：终端选文入口依赖 SwiftTerm `selectedText` API，已确认支持
- **低风险**：`tags.toml` 索引丢失可从片段 frontmatter 重建，但颜色/描述等独立元数据需独立保存策略

## 依赖

- 现有 `SnippetStore` CRUD（已实现）
- 现有 FFI 绑定（`init_snippets`、`list_snippets`、`save_snippet`、`delete_snippet`）
- 现有 SwiftUI `SnippetsView`（已实现）
- SwiftTerm `selectedText` API（已确认支持）

## 后续工作
