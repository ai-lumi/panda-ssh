# 消解基线冲突

> 状态：草案 | 创建日期：2026-09-09 | 关联路线图：brainstorming-ai-era-roadmap.md 1.3、#33

## 问题

路线图 1.3 识别三处基线冲突，阻碍后续提案与实施：

1. **凭据存储**：AGENTS.md 宣称"密码、私钥口令只存系统钥匙串"，但 `auth/spec.md`、`credential-protection/spec.md` 与 `credentials.rs` 实现均支持本地凭据文件（可选加密），不依赖系统钥匙串。
2. **连接池残留条款**：`connection-pool/spec.md` 第 82–100 行「连接复用」为早期设计残留；后续因复用导致多 SSH 连接异常，改为按所有者独占（第 9–80 行），但残留条款未清理。
3. **片段状态**：`snippets/spec.md` 标注"低优先级，预留"，但 Rust `SnippetStore`、FFI 绑定、SwiftUI `SnippetsView` 已实现 CRUD。

这些冲突导致：
- 文档与实现不一致，无法据此评价产品成熟度
- 新功能设计（巡检、批量执行、跳板机）无法明确连接所有权与凭据访问边界
- 片段深化可能重复建设已验收能力

## 目标

1. 明确当前凭据存储行为，统一 AGENTS.md 与 specs。
2. 清理 `connection-pool/spec.md` 残留复用条款，明确现行设计为所有者独占。
3. 建立片段已实现/已验收/待深化清单，反映当前实现状态。

## 范围

### 包含

- 修订 AGENTS.md 凭据存储描述，与 specs 对齐
- 删除 `connection-pool/spec.md` 第 82–100 行残留复用条款
- 修订 `snippets/spec.md`，区分已实现与待深化能力
- 路线图 1.3 冲突标记为已消解

### 不包含

- 凭据存储架构变更（当前本地文件方案保持不变）
- 连接池实现重构（仅清理规格残留）
- 片段新功能设计（仅建立现状清单）
