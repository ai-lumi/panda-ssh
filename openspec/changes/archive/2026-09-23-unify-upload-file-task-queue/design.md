## Goals / Non-Goals

**Goals:**

- 一个实际文件对应一个可独立排队、查看和控制的任务；组只拥有元数据、目录准备状态和成员关联。
- 执行规则与聚合状态归属 `panda-core`；FFI 转换与转发，Swift 只采集选择、显示状态和回传决策。
- 重用现有队列、扫描能力、目录创建与原生组/行视图，完整接通而非增加第三套上传执行器。

**Non-Goals:**

- 不移除仍有下载或外部调用方使用的批量 API，不为保持旧上传行为新增开关或兼容分支。
- 不改变下载方向的选择交互、路径映射或冲突策略；上传与下载仍须使用同一传输任务、分组、队列、控制、快照和准备操作语义，并保持用户暂停时既有槽位规则。
- 不新增通用扫描进度系统；扫描阶段的跨类型任务入口由 `improve-sftp-task-interactions` 负责。本提案只要求后台扫描和显式错误，目录准备指扫描后的远端建目录。
- 不将文件任务与 SSH 连接池混为一体；本期继续每个执行中文件独占连接。

## Decisions

### 1. 在编排结果中保留文件、目录组和目录准备计划

扫描启动时核心立即登记并返回稳定 `operationID`，固定本次选择的源路径和目标目录；操作快照可查询、可取消，且参与应用停机。扫描只执行一次，复用核心扫描结果及 `aggregate_task_groups`。扫描成功时在同一核心临界区将操作原子交接为所有文件任务和必要的目录组描述，修订号单调递增且摘要按 `operationID` 去重；扫描失败或取消时不登记部分文件任务或远端写入，但保留带源路径的可见终态。FFI 仅转发 `operationID`、快照和控制，业务状态机由核心拥有。

| 选择 | 文件任务 | 目录组 |
| --- | --- | --- |
| 一个文件 | 1 个 | 无 |
| 一个目录，递归含 N 个文件 | N 个 | 1 个，子目录不另建组 |
| N 个独立文件 | N 个 | 无 |
| A、B 两个目录和 x、y 两个独立文件 | A/B 的全部文件加 x、y | A、B 各一组，x/y 无组 |

每次选择中的每个顶层目录使用新 UUID；同次扫描内文件携带相同组 ID。源目录完整路径与组 ID决定归属，不能以目录末级名称反查目录。同名目录、重复上传同一目录均不合并为旧组；重试原任务保留原任务和组 ID。

组计划保留 `sourceRoot`、`destinationRoot` 和扫描所得目录项，避免过滤 `is_dir` 后丢失空目录。原选择中包含父目录及其子目录/文件时按顶层覆盖关系去重；不通过内容哈希去重不同路径文件。

选择替代方案：仅把上传分支改成下载分支的文件循环改动最小，但会丢空目录与批量冲突保护，因此不采用。

### 2. 文件与目录准备共用受控调度，不按组另起传输并发

文件任务和组元数据先统一登记，再启动执行；文件初态为 `Queued`。全部上传入口使用同一个核心 `TransferService`，与既有单文件下载共用额度，当前额度 3 不变。

目录准备是组的内部工作，不是虚构的零字节文件任务。每组按父目录在先的顺序递归创建其目录，准备阶段也申请同一个并发许可证；结束后释放许可证，组内文件再分别申请许可证执行。文件等待本组准备结果时不持有许可证，禁止“组持槽等待子任务、子任务又等槽”的死锁。组在文件传输阶段不额外保留槽位。

独立文件不等待其他目录准备。单文件上传原有 `create_dir_all` 保留，以应对目录被外部删除等正常远端变化。并发创建已存在目录视为成功。

准备阶段按目录路径记录结果，单个目录失败后仍处理可独立准备的兄弟目录。阶段结束后，仅依赖失败目录或其后代路径的文件标记依赖失败，其余成员正常入队；例如空子目录失败不得阻止可写兄弟文件。组保留包含源/目标路径的准备错误，最终聚合为失败。组重试只重做失败目录准备及失败文件，不重复上传已成功成员。空目录组通过自身准备结果结束，文件任务数始终为零。

显式重试失败或已取消文件时，若其父目录准备未成功，核心先以原组 ID 恢复该文件必要的目录准备，随后仅重新调度这个文件，不恢复其他已取消成员。准备工作带执行轮次，取消前的迟到回调不能覆盖新一轮结果。准备成功的目录可被后续重试复用，实际写入前仍执行父目录存在性保障。

组准备接受取消，正在执行的远端调用结束后检查取消，不再开始后续 mkdir；组暂停阻止后续准备步骤及文件启动，继续恢复准备。运行中准备暂停保留其槽位，排队准备暂停不提前取得槽位，与既有传输暂停约定一致。

选择替代方案：文件开始前隐式 mkdir 已覆盖非空目录，但遗漏空目录；另起无限制准备执行器会绕过统一资源限制。故只在既有服务内增加有限的组准备工作，不建设通用作业框架。

### 3. 保留覆盖确认，将决策绑定到文件任务

四种上传都在真实执行、打开目标进行写入之前检查目标存在性，上传不再依赖标签页的预检查结果作为写入许可。复用核心冲突信息结构和异步决策机制，将待决策信息绑定到 `taskID` 和本次请求 ID，Swift 从应用共享任务状态呈现原生覆盖确认。

- 获取许可证后才建连与检查冲突；等待决策时保留该执行槽位，尚未写入文件，UI 显示“等待覆盖确认”，不伪装为持续传输。
- 覆盖仅授权当前文件/本次请求；跳过与默认 300 秒超时跳过均不创建或截断目标，明确显示“已跳过”。不新增覆盖全部规则。
- 取消可中断异步等待；迟到、重复或属于前次重试的决策不作用于新请求。用户暂停时，即便收到覆盖决策，也须等待继续才开始写入。
- 检查目标的错误不得按“文件不存在”处理；权限错误、源文件消失和目标为目录均产生可定位失败，不能静默覆盖。
- 本应用内指向同一主机、同一规范化目标路径的写入按任务串行，后一个在前一个结束后重新检查；此等待在取得全局执行许可证前完成。避免同一目标的两个任务同时获准写入。并不承诺跨应用或服务器外部修改的全局原子锁。
- 来源标签关闭不能销毁决策上下文；等待确认的任务仍可在全局传输页面处理。

核心增加文件任务 `Skipped` 终态与待确认快照，FFI/Swift 同步映射，不以“已完成且已传满文件大小”模拟跳过。既有下载流程不产生新状态，但其状态消费者须完整处理该枚举。

选择替代方案：沿用标签页逐个预确认会把排队前等待、页面生命周期和并发写入检查混在一起；直接默认覆盖会破坏已有数据保护，因此不采用。

### 4. 组生命周期与字节进度分开计算

核心维护组元数据和准备状态，不能只从当前文件数组推导全部目录组，否则空目录与准备失败不可见。文件数只统计真实文件；组头和内部准备不重复计入文件数。

组聚合等待准备及成员终态。失败重试只处理失败准备/文件，不重传完成或跳过文件；单任务控制不影响其他成员，组取消只影响本组未终态工作。

实际上传字节只累加真实文件字节。组保留总大小、已传字节、跳过数量/大小；进度分母可使用总大小减已跳过大小，零分母由准备和成员终态判断，不能因为总大小为零提前标记完成。显示完成且包含跳过时附“跳过 N 项”，不将跳过字节记为已上传。

任务重试保留 ID、源/目标路径与组关联，重新检查当前目标冲突。清除已完成可清理成功、取消、跳过记录及不再有可见成员的终态组；失败组及失败准备仍保留供重试。

选择替代方案：直接使用现有 `tasks.groupBy(groupID)` 无法表示零文件组；单用字节比例也无法表达跳过和空目录结果，因此保留最小的显式组记录。

### 5. 接通 FFI、上传入口、轮询和原生展示

FFI 启动编排时立即返回 `operationID`；扫描完成后，快照返回文件任务 ID、目录组 ID及目录准备信息，不把新上传目录放在 `batchIds`。上传和下载按方向保留各自路径映射和选择输入，但共享任务、组、队列、控制、快照和操作生命周期。任务/组快照提供待确认、跳过及准备错误；冲突决策接口明确指定任务和请求 ID。

选择、扫描、建目录、排队与冲突策略由核心决定。FFI 保持同步导出和既有全局 runtime 适配，后台执行不能嵌套阻塞 tokio worker；桥接只负责 DTO 和执行资源适配，不在 Swift 重新聚合业务状态，也不在 FFI 选超时/并发策略。已完成的迁移提案不限制本接口演进，但不构成把业务重新放回 FFI 的例外。

Swift 四种上传入口统一消费结果：

- 只有文件任务的选择不生成组头；包含目录时读取核心组快照，即便该组暂无文件也展示其准备/结果。
- 上传完成登记后确保刷新和启动轮询，只有目录准备或待确认时同样可见；不能依赖先前存在另一个单文件任务才开始刷新。
- 组头展开已有 `GroupRow` 成员视图；文件行的“查看完整路径”显示自身绝对源/目标文件路径。长路径实际点击后不截断；短路径允许内容无变化，但按钮文案应切换。
- 文件任务与组 UUID 稳定，进度刷新、同名目录和重试不重置展开状态。整个页面重建不承诺保存临时展开偏好。
- 保留旧批量快照消费者供未迁移下载/API 使用；新上传不产生第二份批量条目。源码删除只针对确认不再使用的上传分支。

选择替代方案：重新手写目录列表或路径详情页面并不能修复执行粒度，故优先复用已有原生组件。

### 6. 扫描与失败边界

本地扫描运行在后台并复用当前符号链接循环处理。启动即返回的 `operationID` 允许 UI 在扫描尚未生成文件任务时查询进度、展示不定进度、取消或参与停机。整个选择扫描失败时操作进入包含源路径的可见失败终态，不将失败吞成空选择、不登记部分可执行上传，也不提前产生远端写入；用户可以修正选择后重新启动操作。

扫描成功后文件任务全部可见，大量文件只增加排队记录，不预先为每个文件建连。排队期间文件消失时仅对应文件失败；目录准备及文件失败均包含源和目标路径。内存复杂度仍为扫描与文件快照的 O(N)，本期不增加持久化队列或惰性分页。

## Risks / Trade-offs

- [小文件逐文件建连较慢] → 保持受控并发及连接隔离，使用本地 fake SSH/SFTP 服务验证连接峰值与大目录响应；连接池留待独立提案，不回退为目录黑盒任务。
- [目录准备占用额度暂时减少文件并发] → 准备后立即释放；空目录和建目录同样受限制，避免组数越多连接越多。
- [三个槽位都等待覆盖确认] → UI 显示等待原因、允许取消，沿用有界超时跳过；不是新增队列死锁，也不私自扩大并发。
- [新增跳过/组准备状态遗漏消费者] → 同步更新核心聚合、FFI 枚举与契约、Swift 状态映射、计数和清理测试，回归下载与停机摘要。
- [共享基础有其他未提交改动] → 实施前复核实际工作区，保持现有改动；不得恢复旧快照或按文件覆盖实现。
- [旧规格/其他提案归档覆盖新模型] → 同时更新三个能力的 delta；归档前检查相关活动提案，不能用旧“目录单批量任务”覆盖本提案。

## Migration Plan

1. 评审本提案后才开始实现；本次只提交可评审文档产物，不创建代码提交。
2. 按 `tasks.md` 顺序为编排、准备、冲突、调度、FFI 和 Swift 先添加失败测试，再完成最小实现。先稳定核心和桥接契约，再切换上传 UI。
3. 生成绑定并双端构建，使用假服务与受控临时文件验证四种模式、队列满、空目录、覆盖/跳过、关闭来源标签和长路径。真实网络上传与屏幕采集需要另行明确授权。
4. 与 `improve-sftp-task-interactions` 对齐：该提案负责删除、统一任务入口和扫描可见性，并服从本提案对目录上传逐文件执行粒度的优先级；两份活动文档在实施前同步移除“保留目录批量上传路由”的前提。已完成的 `migrate-business-logic-to-rust` 不约束接口演进；本提案独立保证核心业务所有权与 FFI 薄桥边界。
5. 为新增准备、跳过、冲突和失败文案指定 Swift 或 Rust 的唯一资源所有者，补齐中英资源和复数模板，并通过 `check-localization-completeness` 后再归档。
6. 验收与覆盖率通过后，将本提案增量合并到当前主规格并归档；旧“目录复用单连接的批量执行”上传要求被明确替换。不得归档未完成实现。
7. 队列不跨应用重启持久化，本期无存储迁移。版本回退只适用于无在途任务时整体回退应用，不运行中转换任务，不增加双模型兼容开关。
