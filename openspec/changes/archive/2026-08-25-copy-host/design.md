## Context

当前侧栏 sheet 只区分新增与编辑，`HostEditView` 以可选的现有主机决定表单标题和保存 ID。复制需要复用现有编辑表单，但不能把来源 ID 或敏感状态带入新记录。

## Goals / Non-Goals

**Goals:**

- 让菜单动作明确表达“从来源预填的新建”，避免通过伪造编辑对象实现。
- 在表单初始化处集中定义哪些字段可以复制、哪些字段必须清空。

**Non-Goals:**

- 不引入批量复制、复制后自动命名或即时保存。
- 不读取、传递或复制敏感凭据。

## Decisions

### 使用专用 sheet 路由状态

新增复制 sheet case，携带不可变来源主机；路由创建新建模式的 `HostEditView` 并传入预填数据。备选方案是将来源主机当作编辑对象传入再覆盖 ID；该方案容易误保存回原对象，因此拒绝。

### 表单层构建白名单预填模型

只从来源主机复制规格允许的普通字段。认证方式和私钥路径是连接配置而非秘密，可复制；密码、口令、凭据保存标记、凭据引用、指纹和演示/连接状态全部重置。保存时仍由新建分支生成 UUID 和未验证状态。

## Risks / Trade-offs

- [名称重复] → 允许用户在保存前修改；当前主机规则未要求名称唯一。
- [认证方式为私钥但路径在目标设备不可用] → 保留既有私钥选择/连接错误行为，本提案不新增跨设备路径处理。
- [菜单入口不一致] → 用同一 `HostRowView` context menu 供 macOS/iPadOS 共用，并以 SwiftUI 测试或可验证的状态转换覆盖。

## Migration Plan

无需持久化迁移。先增加失败测试验证预填与敏感状态清空，再实现路由与表单参数，最后编译 macOS/iPadOS target。
