## 十、场景化产品设计

> #14 修订：保留 22 个候选场景，移除未经验证的「真实高频」与覆盖度统计。角色和频率是待访谈假设；有 SSH 原语不代表完整业务场景已经被产品满足。

### 10.1 场景清单与能力映射

| # | 候选场景 | 所需增量/限制 | 推进条件 |
|---|----------|---------------|----------|
| 1 | 服务器健康巡检 | 批量采集、测量契约、业务验证与审计 | 首个闭环候选；人工成功验证后可启用 macOS 定时 |
| 2 | 日志查看与聚合 | 明确数据范围、时间与来源，限制输出 | 先单机/少量主机；外部日志 MCP 按需求追加 |
| 3 | 服务重启与状态检查 | 变更审批、后置健康检查、结果未知处理 | G1 后，先明确服务与权限边界 |
| 4 | 滚动更新部署 | 批次、健康门禁、版本锁定、补偿与停止策略 | 单独高风险提案，不能由并行 exec 推导已覆盖 |
| 5 | 配置文件批量分发 | 目标内容预览、冲突与备份、部分失败 | 先定义单向分发；完整同步另见 10.4 |
| 6 | 性能瓶颈诊断 | 时间一致的指标、竞争假设与验证 | AI 增益实验候选，不自动确认根因 |
| 7 | 网络连通性排查 | 跳板链、明确探测范围和权限 | 跳板机尚待实现；不自动扫描内网 |
| 8 | SSH 密钥审计与轮换 | 公开密钥清单与有效性判断、避免锁死恢复路径 | 单独提案，不向 AI 暴露私钥或凭据 |
| 9 | 安全加固与合规检查 | 基准版本、适用系统、检查证据与权限 | 未按基准验收前仅称检查报告，不声称认证合规 |
| 10 | 应急响应与入侵排查 | 证据采集范围、低扰动与人工变更审批 | 紧急状态不突破授权或审计边界 |
| 11 | 数据库备份与恢复验证 | 备份一致性、恢复环境、真实恢复检查 | 不能只用文件校验和宣称可恢复；不先做通用编排 |
| 12 | 数据库主从切换 | 复制一致性、脑裂防护、版本特定步骤 | 高风险独立提案，不承诺通用回滚 |
| 13 | 远程开发环境 | 工作区恢复、SSH 重连、远端进程恢复分别设计 | 远端连续性不能只靠客户端重连 |
| 14 | 远程应用调试 | 日志定位与证据关联 | 先验证简单搜索/规则，再增加语义检索 |
| 15 | SSH 隧道访问内网 | 本地转发、监听范围、端口冲突、保活 | 基础能力方向，具体规模与需求待验收 |
| 16 | 反向隧道 | 远端监听范围、服务端策略与关闭生命周期 | 不默认开放公网监听 |
| 17 | SOCKS 代理 | 动态转发与访问范围 | 独立转发类型，不能用本地转发覆盖数冒充实现 |
| 18 | K8s 节点故障排查 | 集群上下文、RBAC、节点/服务证据 | 外部 MCP 或受控命令按环境选，不能假定节点自带有效 kubectl 凭据 |
| 19 | 容器镜像与存储清理 | 引用关系、保留策略、删除预览 | 写操作单独审核，不套用定时只读巡检授权 |
| 20 | 批量安全补丁更新 | 平台差异、维护窗口、重启与失败恢复 | 高风险变更提案，不能视为 Phase 1 默认覆盖 |
| 21 | 批量用户与权限管理 | 身份映射、权限差异、验证与恢复 | 明确目标范围与变更后访问能力 |
| 22 | 操作审计与会话回放 | 命令审计、缺段检测、可选录像 | 审计为执行基础；录像按需求扩展，不能互相替代 |

### 10.2 场景覆盖度分析

当前只能确认基础 SSH/SFTP、主机管理、部分片段与工作区能力存在；每个场景的端到端支持情况须对照规格与实际验收，不能把「可手动输入相关命令」算作产品完整覆盖。

不再使用原来的 3/7/6/4/2 覆盖数：原表重复计算部分场景、遗漏 SOCKS，且将尚未实现的跳板机列为已有。使用上述 22 个唯一编号追踪到提案和验收证据；未验收即标为候选。

### 10.3 场景驱动的 Skill 规划

#### 内置 Skill 候选

保留日常巡检、深度巡检、批量命令执行、日志检索、性能诊断、安全合规六个方向。第一批只完成一个巡检闭环及一个排障验证样例，其余按需求排序，不把六个同时交付作为阶段门槛。

Skill 是方案入口，执行时生成明确计划并经审核。定时巡检仅 macOS，且需首次人工审核、人工执行验证无问题后由用户启用。批量变更、清理或修复不因使用 Skill 而自动取得周期授权。

#### 扩展 Skill 候选

K8s、容器、数据库、滚动部署与跨系统日志等按真实环境另立提案。先确认工具权限、版本、数据边界及失败恢复，再选择 MCP Server；「存在 MCP Server」不等于场景已完成。

### 10.4 场景驱动的产品能力缺口

| 能力 | 必须先说明的契约 |
|------|------------------|
| 审计 | 本地命令历史、连续性检查、删除后缺段可见；格式/存储后续设计 |
| 批量执行 | 有界资源、部分失败、取消、结果未知、重试与业务验证 |
| 恢复 | 标签/显示恢复、SSH 重连、远端进程恢复分别承诺 |
| 定时巡检 | macOS 准入与授权失效，退出/睡眠/错过/重叠策略；iPadOS 不支持，无服务器中转执行 |
| 跨主机同步 | 单向或双向、内容比较、冲突、删除传播、符号链接、权限/元数据、部分失败、临时落地数据及带宽 |
| 主机选择 | 主机标签与片段标签分开；分组选择在审批时固定为具体集合 |
| 环境兼容 | 远端操作系统、工具版本、locale、权限与依赖缺失，不能全归为一个正则问题 |

### 10.5 场景 × 验证关卡

| 场景组 | 首要验证 | 扩展条件 |
|--------|----------|----------|
| 巡检与批量采集 | G1：授权、有效测量、结果未知、审计缺段 | 首次人工验证成功，用户才可启用 macOS 定时 |
| 日志与故障初筛 | G2：相对人工/规则的投入下降与诊断质量 | 证明增益后增加 AI、记忆或拓扑 |
| 发布/权限/数据库等变更 | 专项失败恢复、业务验证与权限测试 | 不凭已有执行原语或模型建议提前放行 |
| 团队与生态 | 共享范围、访问控制、来源版本与真实需求 | 前期闭环有效后逐项推进 |

### 10.6 关键洞察

场景列表用于发现问题，不用于证明市场规模或自动确定优先级。近期关注完成一次可核对巡检需要多少人工操作、失败时是否安全、审计是否连续，以及 AI 是否减少总人工负担。无法重复验证的增益不应驱动提前建设完整平台。
