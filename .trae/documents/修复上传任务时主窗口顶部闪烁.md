# 修复上传任务时主窗口顶部闪烁

## Context（为什么要改）

**问题现象**：有上传任务（或任何活跃传输任务）运行时，主窗口顶部 chrome（页签栏 + 侧栏工具区）会持续闪烁。

**根因**：
1. `PandaSSHApp.swift` L31-33 通过 `.environmentObject(transfers)` 把 `TransferStore` 注入主窗口环境。
2. `WorkspaceView.swift` L9 用 `@EnvironmentObject private var transfers: TransferStore` 持有它 → SwiftUI 把 `WorkspaceView.body` 与 `TransferStore.objectWillChange` 绑定。
3. `TransferStore` 在有活跃任务时启动 5Hz `Timer.publish`（`TransferStore.swift` L954-968），`tick()` 每 0.2s 重新构造 `tasks` 数组（L704-719）并广播 `@Published`。
4. `WorkspaceView.body`（L54-75 的 `macOSBody`）内嵌 `UnifiedWorkspaceChrome` → `UnifiedWorkspaceTabStrip`，二者未实现 `Equatable`，所以每次 body 重评估时它们的 body 也被强制重评估。
5. `UnifiedWorkspaceTabStrip` 每次 body 重评估重新发布 `UnifiedTabFramePreference` → `.onPreferenceChange` → `revealActiveTab` → 几何重算循环，肉眼上看就是顶部闪烁。

**目标**：切断 `WorkspaceView` 与 `TransferStore` 的订阅关系，让顶部 chrome 不再被 5Hz tick 触发重评估；同时 `TransferPageView` 和 SFTP 标签页仍能拿到 `transfers` 实例正常工作。

## 推荐方案：路由视图隔离 + TransferPageView 环境化

### 关键约束（来自 Plan agent 验证）

- **`SftpTabView` 不能直接改 `@EnvironmentObject transfers`**：`SftpTabView.swift` L48-53 的 `session` 是 `@StateObject`，init 时必须把 `transfers` 传给 `SftpSessionStore(host:transfers:)`。`@EnvironmentObject` 在 View 的 `init()` 里访问会触发 `FatalError: No ObservableObject of type TransferStore found`（环境在 body 评估前未传播到 self）。
- 因此不能简单删 SftpTabView 的 init 参数。需要引入一个**路由视图** `SftpTabsCollection` 持有 `@EnvironmentObject transfers`，再经 init 参数把 transfers 传给 SftpTabView。

### 改动清单

#### A. `apple/PandaSSH/Workspace/WorkspaceView.swift`

- 删除 L9 `@EnvironmentObject private var transfers: TransferStore`
- L307 `case .transfers: TransferPageView(store: transfers)` → `case .transfers: TransferPageView()`
- L334 `sftpTabs(policy: sftpPolicy)` → `SftpTabsCollection(policy: sftpPolicy)`
- 删除 L393-405 的 `sftpTabs(policy:)` 方法（逻辑迁移到 `SftpTabsCollection`）

#### B. `apple/PandaSSH/Workspace/TransferPanelView.swift`

- L4-5 `@ObservedObject var store: TransferStore` → `@EnvironmentObject private var store: TransferStore`（删除隐式合成的 init；@EnvironmentObject 不需要 init 参数）
- L366 Preview：`TransferPageView(store: store)` → `TransferPageView().environmentObject(store).environmentObject(AppModel.previewModel())`

#### C. `apple/PandaSSH/PandaSSHApp.swift`

- L58-61 传输任务窗口：
  ```swift

  ```

#### D. 新增 `apple/PandaSSH/Workspace/SftpTabsCollection.swift`

```swift
import SwiftUI

/// SFTP 标签集合容器:独占订阅 TransferStore,把 5Hz tick 的 body 重评估
/// 隔离在本视图内,避免向上传到 WorkspaceView 触发 chrome 重渲染。
/// SftpTabView 自身不持有 @EnvironmentObject transfers,其 @StateObject session
/// 经 init 参数拿到同一实例,StateObject 生命周期与 ForEach id 一致。
struct SftpTabsCollection: View {
    @EnvironmentObject private var model: AppModel
    @EnvironmentObject private var transfers: TransferStore

    private let policy: WorkspaceSftpTabPolicy

    init(policy: WorkspaceSftpTabPolicy) {
        self.policy = policy
    }

    var body: some View {
        ForEach(policy.retainedTabs) { tab in
            if let host = model.hosts.first(where: { $0.id == tab.hostID }) {
                let isVisible = policy.isVisible(tab.id)
                SftpTabView(tab: tab, host: host, transfers: transfers)
                    .opacity(isVisible ? 1 : 0)
                    .allowsHitTesting(isVisible)
                    .accessibilityHidden(!isVisible)
                    .zIndex(isVisible ? 1 : 0)
            }
        }
    }
}
```

**为什么用路由视图而不是给 SftpTabView 加 env**：
1. 不破坏 SftpTabView 的 `@StateObject session` 初始化链（不需要 env-in-autoclosure 这种不可靠模式）。
2. SftpTabView.body 不再每 0.2s 被无意义重评估（避免文件浏览器 GeometryReader + ForEach 高频刷新）。
3. 路由视图 body 只是 ForEach，5Hz 重评估几乎零成本；ForEach 内 SftpTabView 的 init 参数稳定（tab/host/transfers 都不变），SwiftUI 跳过 SftpTabView.body 重评估。
4. `SftpSessionStore.observeCompletedTransfers()`（Combine 订阅 `transfers.$tasks`）照常工作，传输完成时文件列表刷新逻辑不变。

### 2. 手动验证闪烁消失

1. 启动 macOS App（真实后端）
2. 连 SFTP 主机，上传大文件（触发 5Hz tick）
3. tick 期间观察主窗口顶部 chrome：tab strip 不应每 0.2s 抖动、滚动锚点不应反复重算
4. 同时打开「传输任务」窗口（Window → 传输任务），确认进度条仍然 5Hz 刷新（说明 transfers tick 路径仍工作，只是不再传到 chrome）
5. 切换侧栏到「传输」页，确认进度仍然实时刷新

### 3. 几何回归

tick 期间：
- 添加 / 关闭 SFTP 标签 → tab strip 正常滚动到活动 tab
- 侧栏显隐切换 → chrome 宽度重分配无异常
- 多 SFTP 标签切换 → 文件列表保持各自 session（StateObject 不被销毁）

## 风险与回滚

| 风险 | 影响 | 缓解 |
|---|---|---|
| 传输任务窗口漏注入 transfers → 打开窗口 crash | 用户立即发现 | 改动 C 显式补 `.environmentObject(transfers)`；ViewCoverageTests E 覆盖 |
| `TransferPageView` Preview 缺 env → canvas crash | 仅影响 Xcode Preview | 改动 B 显式补 `.environmentObject(store)` |
| 删 `page?.store === store` 断言后覆盖率下降 | 该断言不覆盖真实业务行为 | 已通过 `store.tasks` 断言保护核心行为 |
| `SftpTabsCollection` body 5Hz 重评估 | 微小 CPU 开销 | 与原 `sftpTabs(policy:)` 行为一致，不退化 |

回滚：纯 SwiftUI 视图层重构，无数据/逻辑变更，无 FFI/Rust 改动。`git revert` 单个 commit 即可，无持久化副作用。

## 不采用的补充优化

- **给 UnifiedWorkspaceChrome / UnifiedWorkspaceTabStrip 实现 Equatable**：路由方案已切断根因，Equatable 边际收益小，且这两个 View 依赖大量 @State/env，加 Equatable 容易遗漏导致行为变化。本次不做。
- **调整 TransferStore tick 频率**：5Hz 对进度条流畅度合理，根因不在频率，不应改。
- **处理 PreferenceKey 循环**：`scroll(to:)` 已有 `> 0.5` 阈值保护，循环有界；路由方案落地后只在真正几何变化时触发，是预期行为。
